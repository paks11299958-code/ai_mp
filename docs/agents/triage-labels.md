## 성격 — 셋 중 **하나만** 붙인다 (필수)

모든 이슈는 아래 셋 중 정확히 하나를 갖는다. 서로 배타적이다.

| 라벨 | 색 | 언제 붙이나 | 판별 기준 |
|---|---|---|---|
| `bug` | `#d73a4a` | 동작이 잘못됨 — 고쳐야 하는 결함 | **원래 되던 것/되어야 하는 것이 안 된다** |
| `feature` | `#a2eeef` | 새 기능 또는 기존 기능 확장 | **지금까지 없던 것을 만든다** |
| `chore` | `#cfd3d7` | 정리·문서·설정·리팩터링 등 기능 외 작업 | **회원 화면에 보이는 변화가 없다** |

**헷갈리는 경계:**
- "느리다" → 기준보다 느려졌으면 `bug`, 원래 느렸는데 빠르게 하고 싶으면 `feature`
- "안내 문구가 이상하다" → 잘못된 정보면 `bug`, 더 낫게 다듬는 거면 `chore`
- 리팩터링 → `chore`. 단 **그 과정에서 동작이 바뀌면 `feature`나 `bug`로 재분류**한다
- ★**"빠졌다"가 항상 결함은 아니다.** 카드가 없는 기능은 정상일 수 있다.
  결함이라 단정하기 전에 기존 사례와 대조한다 → `needs-check`

## 상태 — 해당될 때만 **추가로** 붙인다 (선택)

성격 라벨 위에 덧붙인다. 없어도 되고, 둘 다 붙어도 된다.

| 라벨 | 색 | 뜻 | 뗄 시점 |
|---|---|---|---|
| `blocked` | `#b60205` | 선행 작업·외부 요인 때문에 진행 불가 | 막힌 게 풀리면 즉시 |
| `needs-check` | `#fbca04` | 사실 확인·실측이 먼저 필요함 | 실측값이 나오면 즉시 |

### `blocked`
★**무엇에 막혔는지 코멘트로 반드시 남긴다.** 라벨만 붙으면 왜 멈췄는지 아무도 모른다.
- 다른 이슈 대기 → `#8에 막힘`처럼 번호를 적는다
- 사장 결정 대기 → 무엇을 정해야 하는지 적는다
- 외부 요인(쿼터, API 승인 등) → 무엇을 기다리는지 적는다

### `needs-check`
**추정으로 진행하면 안 되는 이슈**에 붙인다. 이 프로젝트에서 반복된 사고 유형이다.
- 원가·성능·용량을 **추정값으로 적었을 때** → 실측 전까지 유지
- "안 된다"고 보고됐지만 **재현이 안 됐을 때**
- 모델·라이브러리 도입 검토 → ★**라이선스 확인 전까지 유지**
- "코드를 넣었다"까지만 되고 **효과 실측이 없을 때**

★이 라벨이 붙은 이슈는 **닫을 때 실측값을 코멘트에 남겨야 한다.**

## 붙이지 않는 것

- **담당자 라벨(`codex`/`claude`)은 만들지 않는다.** 누가 하는지는 **코멘트**로 남긴다.
  라벨로 고정하면 손이 빈 쪽이 못 집는다.
- **우선순위 라벨(`P0`~`P3`)은 만들지 않는다.** 순서는 사장이 정한다.
- **상태 라벨(`todo`/`doing`/`done`)은 만들지 않는다.**
  열림/닫힘과 코멘트로 충분하고, 라벨과 실제 상태가 어긋나기 시작하면 더 헷갈린다.
