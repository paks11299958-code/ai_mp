## CONTEXT.md를 읽는 때

**용어를 쓰기 직전에 읽는다.** 특히 아래 상황에서:

- **이슈 제목·본문을 쓸 때** → 제목의 용어를 `CONTEXT.md` 표기로 맞춘다
- **코드·모듈 이름을 지을 때** → 도메인 개념은 `CONTEXT.md` 용어를 따른다
- **사장에게 보고할 때** → 같은 개념을 매번 다른 말로 부르지 않는다

★**동의어로 흘리지 않는다.** `CONTEXT.md`가 "쇼츠"로 정했으면 "숏츠"·"쇼트폼"으로 쓰지 않는다.
Codex와 Claude가 서로 다른 말을 쓰면 **같은 일이 중복 이슈로 두 번 등록된다.**
이슈 검색(`gh issue list --search`)도 용어가 갈리면 못 찾는다.

## CONTEXT.md를 고치는 때

- **새 도메인 개념이 생겼을 때** — 기능을 추가하며 새 용어를 만들었으면 그 자리에서 추가한다
- **용어가 흐릿해서 헷갈렸을 때** — 헷갈린 그 순간에 정의를 날카롭게 고친다
- **정본 문서가 새로 생겼을 때** — 지도에 한 줄 추가한다

파일이 없으면 **그때 만든다**(lazy). 미리 채워두지 않는다.

★고칠 때 **내용을 복사해 오지 않는다.** "이 개념은 어느 문서가 정본인가"만 가리킨다.

## docs/adr/ — 결정 기록

### 형식은 아주 가볍다

파일명은 순번 + 슬러그: `0001-flux1-dev-not-adopted.md`, `0002-....md`
새 번호는 `docs/adr/`에서 가장 큰 번호 + 1.

```md
# {결정을 한 줄로}

{1~3문장: 어떤 맥락이었고, 무엇으로 정했고, 왜인가.}
```

이게 전부다. **한 문단이면 충분하다.** 칸을 채우는 게 목적이 아니라
**"결정이 있었다"와 "왜"를 남기는 것**이 목적이다.

선택 항목(대부분 필요 없다):
- **Status** — `proposed | accepted | deprecated | superseded by ADR-NNNN`. 결정이 뒤집힐 때만
- **검토한 대안** — 탈락시킨 안을 기억할 가치가 있을 때만
- **결과** — 눈에 안 띄는 부작용이 있을 때만

### 언제 ADR을 쓰나 — 셋 다 만족할 때만

1. **되돌리기 어렵다** — 나중에 마음을 바꾸는 비용이 크다
2. **맥락 없이 보면 의아하다** — 미래의 독자가 "왜 이렇게 했지?"라고 물을 것이다
3. **진짜 트레이드오프였다** — 실제 대안이 있었고 이유가 있어서 하나를 골랐다

되돌리기 쉬우면 쓰지 않는다(어차피 되돌린다).
의아하지 않으면 아무도 안 궁금해한다. 대안이 없었으면 기록할 게 없다.

### 이 프로젝트에서 특히 ADR감인 것

★**"안 하기로 한 결정"이 가장 값지다.** 기록이 없으면 **몇 달 뒤 똑같이 다시 제안된다.**
실제로 2026-08-22에 이미 결론 난 모델을 다시 권유받았다.

- **모델·라이브러리를 안 쓰기로 한 결정** — 특히 **라이선스** 때문일 때
  (비상업 라이선스는 품질과 무관하게 탈락이다. 품질만 보고 다시 제안되기 쉽다)
- **장비·아키텍처를 그대로 두기로 한 결정** — 왜 안 바꿨는지가 안 보인다
- **도구를 도입하지 않기로 한 결정** — 매력적으로 보이는 도구일수록 다시 올라온다
- **콘텐츠·정책 경계** — 형태를 바꿔 재요청되기 쉽다
- **A/B로 뒤집힌 통념** — "최신 모델 = 더 좋음"이 아니었던 사례들

### ADR을 읽는 때

★**새 도구·모델·라이브러리를 제안하거나 검토하기 전에 `docs/adr/`를 먼저 훑는다.**
이미 탈락시킨 것을 다시 조사하면 시간을 통째로 버린다.

```sh
ls docs/adr/
grep -rn "키워드" docs/adr/
```

### ADR과 이슈의 차이

- **이슈** = 할 일. 끝나면 닫힌다.
- **ADR** = 결정. **닫히지 않는다.** 뒤집힐 때 새 ADR이 이전 것을 대체(`superseded`)한다.

이슈를 "안 하기로" 닫았는데 그 판단이 **되돌리기 어렵고 다시 제안될 만하면**, ADR로 올린다.

---

## 과거 결정은 소급 정리하지 않는다

`docs/adr/`는 **새 결정부터** 쌓는다. 과거 결정을 전부 ADR로 옮기지 않는다.
예외는 위 "특히 ADR감인 것"에 해당하면서 **실제로 다시 제안된 적이 있는 것**뿐이다.
