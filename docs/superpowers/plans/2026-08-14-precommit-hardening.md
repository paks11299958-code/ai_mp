# pre-commit 훅 강화 구현 계획

> 작성 2026-08-14 · 브레인스토밍 결론에 따른 1단계(B안: 기계적 강제)

## 목표

**"짠 놈이 검사까지 하니 자기 실수를 못 본다"** — 이 구조적 약점을 기계로 막는다.
AI가 "완료했습니다"라고 말해도, 검증을 안 통과하면 커밋 자체가 되지 않게 한다.

### 배경 사고 (사장님 메모리 기록)

| 사고 | 원인 | 지금 훅이 막나 |
|---|---|---|
| 운영 백지 (2026-07-28) | tsc는 TDZ를 못 잡음 | ❌ |
| 번들 해시로 배포 판단 (2회 반복) | 검사 항목 자체가 없음 | ❌ |
| "코드 넣음 ≠ 효과 있음" | 실동작 검증 없음 | ❌ |
| api/·scripts/ 수정 | **검사 대상이 아님** | ❌ |

## 범위 밖 (명시적 제외)

- ❌ **웹 지시함·큐·브리지** — 사장님 불만(품질)과 무관. 브레인스토밍에서 폐기
- ❌ **SaaS 멀티테넌트** — 지금 목표 아님
- ❌ **자동 배포** — 배포 승인은 반드시 사장님이 (확정)
- ⏸️ **AI 검토자(A안)** — 이번 단계 완료 후 별건으로 검토

## ★ 실측으로 드러난 핵심 제약

### smoke는 pre-commit에 넣을 수 없다

`scripts/smoke-test.cjs` 주석에 명시되어 있다:

> ★반드시 **배포 후 운영 URL**에 대고 돌릴 것. 로컬 프리뷰는 API 프록시가 없어
> 토큰을 심어도 로그인 상태가 되지 않는다 — 실제로 2026-07-28 사고 코드를
> 로컬 프리뷰로 검사했을 때 "정상"으로 통과했다.

**즉 커밋 시점에는 아직 배포가 안 됐으므로 smoke가 검사할 대상이 없다.**
브레인스토밍 때 "훅에 smoke를 넣자"고 했던 건 **철회한다.** 넣으면 무의미한 통과만 반복된다.

→ smoke는 **배포 후 단계**로 분리한다 (태스크 5).

### 소요시간 실측

| 검사 | 시간 | pre-commit 적합 |
|---|---|---|
| `check-react-safety.cjs` | **0초** | ✅ |
| `tsc --noEmit` | **5초** | ✅ |
| `smoke` (운영 브라우저) | 수십 초 + 배포 필요 | ❌ |

현재 훅(check + tsc)은 약 5초. 여기에 몇 초 더 붙는 건 감당 가능하다.

## 현재 상태

`.git/hooks/pre-commit` (기존, 25줄)

```bash
STAGED=$(git diff --cached --name-only --diff-filter=ACM | grep -E '^frontend/.*\.(ts|tsx)$')
[ -z "$STAGED" ] && exit 0     # ← 프론트 외 파일은 전부 무검사
node scripts/check-react-safety.cjs
(cd frontend && npx tsc --noEmit)
```

**구멍:**
1. `api/`, `scripts/`, `prisma/` 수정 시 **아무 검사도 안 함**
2. `--no-verify`로 우회 가능 (안내 문구까지 있음)
3. 훅이 `.git/hooks/`에만 있어 **git에 추적되지 않음** → 백업·재현 불가

## 태스크 체크리스트

### 태스크 1 — 훅을 git 추적 대상으로 이동 (20분)

- [ ] 기존 `.git/hooks/pre-commit`을 `scripts/hooks/pre-commit`으로 복사
- [ ] `scripts/install-hooks.sh` 작성 (`.git/hooks/`로 심는 스크립트)
- [ ] 설치 후 기존과 동일 동작 확인 (프론트 파일 스테이징 → 검사 도는지)
- [ ] 커밋

**왜 먼저:** `.git/hooks/`는 백업도 클론도 안 된다. 지금 훅이 날아가면 복구할 방법이 없다.

### 태스크 2 — 검사 범위 확대 (30분)

- [ ] 스테이징 파일 판별을 `frontend/` → 전체 코드 파일로 확대
- [ ] 파일 종류별 분기:
  - `frontend/**/*.{ts,tsx}` → check-react-safety + tsc (기존)
  - `api/**/*.{ts,js}` → 문법 검사 (`node --check`)
  - `prisma/schema.prisma` → `prisma validate`
  - `scripts/**/*.cjs` → `node --check`
- [ ] 문서(`.md`)·설정만 고친 커밋은 기존대로 통과
- [ ] 각 분기가 실제로 도는지 파일 하나씩 스테이징해서 확인
- [ ] 커밋

### 태스크 3 — api/ 정적 검사 스크립트 (30분)

- [ ] `scripts/check-api-safety.cjs` 작성
- [ ] 검사 항목 (과거 사고 기반):
  - [ ] `console.log`에 토큰·비밀번호·API키 노출
  - [ ] `catch {}` 빈 블록 (에러 삼킴)
  - [ ] `setInterval` 재진입 방지 없음 ★전자책 표지 중복생성 사고
- [ ] 기존 `api/` 파일에 돌려 오탐 확인 → 오탐 나오면 규칙 완화
- [ ] 태스크 2의 분기에 연결
- [ ] 커밋

**주의:** 오탐이 많으면 훅을 꺼버리게 된다. 처음엔 확실한 것만 잡는다.

### 태스크 4 — --no-verify 대응 (20분)

- [ ] 훅에서 우회 안내 문구 제거 (지금은 대놓고 알려주고 있음)
- [ ] `scripts/verify.sh` 작성 — 수동으로 전체 검증 돌리는 명령
- [ ] `package.json`에 `"verify"` 스크립트 추가
- [ ] 커밋

**결정 필요:** 우회를 완전히 막을지 여부 → 사장님 확인 후 진행 (아래 "확인 필요" 참조)

### 태스크 5 — 배포 후 smoke 분리 (30분)

- [ ] `scripts/hooks/post-push` 또는 별도 안내 문서 작성
- [ ] 배포 후 실행 순서 문서화: `git push` → Vercel 배포 대기 → `npm run smoke`
- [ ] `npm run verify:deploy` 스크립트 추가 (배포 후 운영 검증용)
- [ ] 커밋

**왜 분리:** smoke는 운영 URL 대상이라 커밋 시점에 못 돈다 (위 제약 참조)

### 태스크 6 — 실사고 재현 테스트 (30분)

- [ ] 과거 사고 패턴을 일부러 만들어 훅이 잡는지 확인
  - [ ] `api/` 파일에 `console.log(token)` 넣고 커밋 시도 → 차단되나
  - [ ] `catch {}` 넣고 커밋 시도 → 차단되나
  - [ ] 문서만 고친 커밋 → 통과하나 (오탐 없나)
- [ ] 결과 기록
- [ ] 커밋

**★이 태스크가 핵심.** 사장님 메모리의 "코드 넣음 ≠ 효과 있음" 교훈 그대로,
훅을 만든 것과 훅이 실제로 막는 것은 다르다. 반드시 실측한다.

### 태스크 7 — 문서화 (20분)

- [ ] `docs/` 에 훅 사용법 기록 (설치·우회·검사항목)

## ★ 확인 필요 (실행 전 사장님 결정)

### 1. `--no-verify` 우회를 막을까?

| 선택 | 장점 | 단점 |
|---|---|---|
| **허용 유지** | 급할 때 막히지 않음 | 급할 때가 사고 나는 때 |
| **완전 차단** | 확실함 | 정말 급할 때 방법이 없음 |
| **차단 + 비상구** | 균형 | 비상구를 습관적으로 쓸 위험 |

→ 브레인스토밍에서 언급했으나 미결. 태스크 4 전에 결정 필요.

### 2. 검사 실패 시 텔레그램 알림?

이미 헤르메스 봇이 있다. 훅이 차단할 때 알림을 보낼 수 있다.
다만 사장님이 직접 커밋하시는 게 아니라 **AI가 커밋하는 상황**이 주 대상이므로,
알림이 유용할 수 있다 (AI가 조용히 `--no-verify`로 넘어가는 걸 감지).

→ 선택사항. 필요하면 태스크 추가.
