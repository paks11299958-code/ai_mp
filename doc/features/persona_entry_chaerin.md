# 윤채린 AI 스튜디오 진입 화면 — 사양서

> 2026-09-06 사장 지시. 도결([[persona_entry_saju]])·서아([[persona_entry_seoa]])에 이은 **세 번째 적용**.
> 겸하여 **진입 랜딩 공통 결함**(기능을 누르면 채팅으로 튕김)을 이때 함께 고쳤다.

## 1. 무엇을 만드는가

페르소나 **윤채린**을 클릭하면 채팅창 대신 **AI 스튜디오 랜딩**이 뜬다.
사진 한 장으로 다른 모습이 되는 것을 **말이 아니라 눈으로** 보여준다.

- 히어로 = **네 살 ↔ 스물다섯 슬라이더**(자동 재생, 손대면 양보)
- **AI 변신 레일** — 지브리풍 · 피규어 · 웹툰 · 헤어
- **촬영 메뉴** — 사진관 가격표 형태(시간여행 100P · 헤어 200P · 전통의상 200P · 닮은꼴 무료)

## 2. ★도결·서아와 다른 점

| | 도결 | 서아 | **윤채린** |
|---|---|---|---|
| `quickMenuJson` | 1,544자(기능 8개) | 0자 | **0자** |
| 기능 성격 | 텍스트 응답(사주 풀이) | 전용 화면(뉴스) | **이미지 변신 보드 4종** |
| 기능 실행 | `/quick-menu-result` 재사용 | `NewsPage` | **기존 보드 그대로**(`FEATURE_ACTIONS`) |
| 창 안 처리 | ✅ 대부분 | — | ❌ **보드를 띄운다**(z-index 제약, §5) |

★윤채린 기능은 전부 **사진 업로드 + 합성**이라 입력 UI가 무겁다. 도결처럼 창 안에서
전부 처리하려면 보드 4개의 입력부를 옮겨와야 하고 **이중과금 위험**이 있어 하지 않았다.

## 3. ★"AI 스튜디오"의 정체 — 사장 지적 3회로 정립

초안은 사진 1장 + 텍스트 카드 2×2였다. 사장 지적이 세 번 있었고 **전부 같은 성격**이었다.

| 지적 | 오진 | 실제 원인 |
|---|---|---|
| "스튜디오 느낌이 안 난다" | **색**을 고치려 함 | **구조** — 그 배치는 앱 설정 화면이다 |
| "AI 느낌이 나야지" | 사진관 사진을 넣음 | **AI가 만든 티**가 나는 결과물이 없었다 |
| "관상은 도결 거 아니냐" | 얼굴 쓴다고 넣음 | 도결 소유(DB 확인 3초) |

결론:
- **스튜디오 = 작품이 격자로 깔려 스스로 말하는 것** (실물 사이트 조사)
- **네컷 = 사진이 여러 장 이어 붙은 것**
- **AI 서비스의 시안이면 AI가 만든 티가 나는 결과물**을 넣어야 정체가 증명된다
  (2026-09 트렌드: 지브리풍은 저물고 **피규어·3D 프로필**이 대세)

정본 교훈: 메모리 `feedback_design_identity_first`.

## 5. ★진입 랜딩 공통 개선 (도결·서아도 함께 적용됨)

사장 지적: "닫으면 모달로 안 띄운 것 아니냐 · 왜 진입페이지로 안 가고 채팅으로 가느냐."

- ✕(`onClose`)는 **원래 정상**이었다 — `setDeepLinkGuide(null)` 뿐, 화면 전환 없음.
- 진짜 원인은 `onFeature` 가 **무조건** `goTo('chat')` 을 부른 것.
- ★**그 전환이 애초에 불필요했다**: 기능 보드가 main·chat **양쪽 return 에 모두**
  렌더돼 있다(App.tsx 1849~ / 2272~). 메인에 머문 채로도 열린다.

**(A) 화면 전환을 조건부로**
- 퀵메뉴형(`FEATURE_QUICK_MENU_LABEL`) = 채팅창에 메시지를 넣는 방식이라 **채팅 필수** → 종전대로
- 보드형(`FEATURE_ACTIONS`) = **그 자리에서** 연다

**(B) 보드를 닫으면 랜딩으로 복귀**
- `entryReturnGuide` 에 복귀 지점을 기억 → 보드 `onClose` 에서 되돌린다
- ★**시트를 열어둔 채 보드를 띄울 수 없다** — 시트 `z-85` vs 보드 `z-50~70` 이라
  **보드가 뒤에 가린다**. 그래서 "닫았다가 되돌아온다"로 풀었다.
- 랜딩을 거치지 않은 평소 경로는 `null` 이라 **종전과 완전히 동일**
