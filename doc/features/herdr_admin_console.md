# 허드 AI 콘솔 — 어드민 통합 기획서

> 2026-08-27 사장 발안. **1~2단계 구현 완료.** 결과·세부 보기는 3~4단계로 남아 있다.
> 사장 요청 원문: *"어드민에 허드AI 메뉴를 만들고 홈페이지·쇼츠·영상·개발 탭으로 나눠
> 파라미터를 받아 허드에 던지고, 결과 리스트에서 소스 다운로드·이미지 보기·사양서 보기까지"*

## 1. 왜 필요한가

지금 허드를 쓰려면 **Claude Code 세션에서 파이썬 스크립트를 짜서 돌려야 한다.**

```python
herdr_project.create("id", "목표", workdir, batches=[...])
herdr_runner.run_next_batch(state, use_review=True)
```

사장이 직접 못 한다. 그래서 실제로는 "사장이 Claude 에게 말한다 → Claude 가 스크립트를
쓴다 → 허드가 돈다"는 **2단 구조**다. 중간 단계를 없애는 것이 이 화면의 목적이다.

## 2. ★먼저 정리해야 할 것 — 이미 5개 탭이 겹친다

새로 만들기 전에 **기존 화면과의 관계를 정해야 한다.** 안 그러면 여섯 번째 탭이 된다.

| 기존 탭 | 무엇인가 | 이 화면과의 관계 |
|---|---|---|
| `devai` **개발AI 콘솔** | 범용 개발 지시(명세·승인·진행). **허드를 실제로 태우는 유일한 화면** | ★**흡수 대상** — 이 화면의 "개발" 탭이 이것이다 |
| `homepage-maker` **홈페이지 생성** | 2026-08-26 Codex 가 만든 UI 뼈대. **백엔드 미연결**(명세 복사까지만) | ★**흡수 대상** — "홈페이지" 탭이 이것이다 |
| `homepage-reqs` 홈페이지 신청 | **회원**이 신청한 것을 운영자가 처리 | 유지 — 목적이 다르다(회원 운영) |
| `shorts` 쇼츠 관리 | 유튜브 업로드 승인 큐 | 유지 — 발행 운영 |
| `codex-shorts` Codex 쇼츠 공장 | 쇼츠 제작 파이프라인 | 검토 필요 — "쇼츠" 탭과 겹칠 수 있다 |

**결론**: 새 메뉴는 `devai` + `homepage-maker` 를 **합치는 것**이지 새로 얹는 것이 아니다.
합치지 않으면 "어디서 개발을 시작하지?"가 세 곳이 된다.

## 3. 화면 구조

```
시스템 > 🐮 허드 AI
├─ [홈페이지]  [쇼츠·영상]  [개발]        ← 만드는 것(입력)
└─ [결과]                                  ← 만들어진 것(목록)
```

### 3-1. 입력 탭 — 종류별로 받는 것이 다르다

**공통**: 프로젝트명 · 목표 한 줄 · **리뷰 켜기 여부** · 예상 비용 안내

| 탭 | 고유 입력 |
|---|---|
| **홈페이지** | 느낌/톤 · 히어로 한 줄 · 핵심 오브젝트 · 움직임 · 기존 내용 출처 · 희망 도메인 |
| **쇼츠·영상** | 소재 · 대본(직접 입력 or AI) · 장면 수 · 화자 · 이미지 생성기(Z-Image/Gemini) |
| **개발** | 대상 저장소 · 건드릴 파일 범위 · 금지 파일 · 완료 조건 |

★**"금지 파일" 입력란은 반드시 넣는다.** 오늘 사주 작업에서 `App.tsx` 를 금지 조항으로
박아둔 덕에 사고를 피했다(2026-07-29 그 파일 수정으로 전 화면 백지 사고).

### 3-2. ★리뷰 켜기는 화면에서 고른다

2026-08-26 에 정리한 기준을 **화면에 그대로 노출**한다. 지금은 코드에 숨어 있어
사장이 판단할 수 없다.

| 작업 | 리뷰 | 화면 표시 |
|---|---|---|
| 신규 기능(API·DB·과금) | ✅ **반드시** | 기본 ON, 끄면 경고 |
| 새 화면·연출 | ✅ 켠다 | 기본 ON |
| 정적 레이아웃·문구 | ❌ 끈다 | 기본 OFF |

★리뷰를 켜면 **호출이 3~4배**다. 화면에 "예상 20~35분 / 리뷰 시 2배"를 적어 둔다.

### 3-3. 결과 탭 — 사장 요청의 핵심

목록에서 각 프로젝트를 열면:

| 세부 | 내용 | 구현 |
|---|---|---|
| **미리보기** | 배포 URL(`deployUrl`) 열기 | ✅ 이미 있음 |
| **이미지 보기** | 생성된 이미지 썸네일 격자 | 신규 — `sites/<name>/assets/` 스캔 |
| **사양서 보기** | SPEC.md 렌더 | 신규 — 마크다운 표시 |
| **소스 다운로드** | zip(`designSourceUrl`) | ✅ 필드 있음, 생성 로직 확인 필요 |
| **리뷰 기록** | Reviewer 가 뭘 지적했나 | 신규 — `state/herdr_receipts/archive/` |
| 진행 이벤트 | 단계별 로그 | ✅ `DevProjectEvent` |

★**리뷰 기록 보기가 특히 값지다.** 2026-08-27 에 영수증을 아카이브로 남기게 고쳤으니
(`archive/<날짜>/`) 이제 **무엇을 지적했고 어떻게 고쳤는지**를 화면에서 볼 수 있다.
그전에는 "미통과"라는 결론만 남고 근거가 증발했다.

## 4. 재사용 — 새로 만들 게 많지 않다

| 필요한 것 | 기존 자산 |
|---|---|
| DB | `DevProject` + `Version`·`File`·`Event`·`Result` **그대로** |
| 생성·시작·승인 API | `admin-devai.ts` 의 `/create` `/start` `/approve` `/sync` **그대로** |
| 동시 실행 1건 제한 | `/start` 에 내장 |
| 허드 실행 | `herdr_project` + `herdr_runner` |
| 리뷰 왕복 | `herdr_review` (2026-08-26·27 버그 3건 수정 완료) |
| 영수증 보관 | `state/herdr_receipts/archive/<날짜>/` |

**신규는 UI 와 조회 API 뿐이다.** 파이프라인은 손대지 않는다.

## 5. 단계

| 단계 | 내용 | 비고 |
|---|---|---|
| **1** | 메뉴 통합 — `devai`·`homepage-maker` 를 `herdr` 아래로. 기존 기능 무손실 | 화면 정리만 |
| **2** | 입력 탭 4종 + 리뷰 토글 → `/create` `/start` 연결 | ✅ 2026-08-27 완료 |
| **3** | 결과 탭 — 목록·미리보기·이벤트 | 조회 위주 |
| **4** | 세부 보기 — 이미지·사양서·리뷰 기록·zip 다운로드 | 사장 요청의 핵심 |

★**1단계를 건너뛰지 말 것.** 입력 화면부터 만들면 개발 시작점이 세 곳이 되어 나중에
어느 것이 정본인지 모르게 된다.

## 6. ★안전 경계 (절대)

- **시작 버튼 누르기 전에는 AI·파이프라인을 호출하지 않는다.** 어드민 화면은 오조작이 쉽다.
- **동시 실행 1건** 상한을 유지한다(서버2 RAM 3.8GB, claude 1개가 3.27GB 먹어 서버가
  멎은 전례가 있다).
- **왕복 상한 `_MAX_ROUNDS=2`** 는 화면에서 못 바꾸게 한다 — 비용 상한이다.
- 배포·DNS 는 **사장이 결과를 본 뒤** 별도 버튼으로. 자동 배포 금지.
- 금지 파일 목록을 사양서에 **그대로 박아** Developer 에게 넘긴다.

## 7. 내 의견 — 사장 안에 덧붙일 것

**① 탭을 "만드는 것 / 만들어진 것"으로 크게 나누는 게 낫다.**
사장 안은 홈페이지·쇼츠·개발 3탭 + 결과인데, 실제로 사장이 하는 일은
**"새로 시킨다"와 "결과를 본다"** 두 가지다. 종류(홈페이지/쇼츠/개발)는 그 안의 선택이다.

**② 사양서 미리보기를 시작 전에 보여줄 것.**
입력을 채우면 **Developer 에게 실제로 갈 지시문**을 보여주고 "이대로 시작"을 누르게 한다.
지금 `homepage-maker` 의 "명세 복사" 가 그 역할인데, 복사 대신 **바로 시작**으로 잇는다.
★오늘 확인된 것: 사양서에 함정을 미리 박으면 리뷰로 잡는 것보다 싸다. 그러려면 **사장이
시작 전에 사양서를 볼 수 있어야** 한다.

**③ "이어서 하기"를 화면에 노출할 것.**
허드는 묶음 단위로 돌고 중간에 멈출 수 있다(`/hermes 이어서 <ID>`). 지금은 텔레그램
명령으로만 되는데, 결과 목록에서 **[다음 묶음 실행]** 버튼이면 충분하다.

**④ 비용을 화면에 보여줄 것.**
묶음당 20~35분, 리뷰 켜면 2배. GPU 이미지 생성은 별도(기동비가 원가를 지배 —
5장에 340원). 시작 전에 예상치를, 결과에 실제치를 보여주면 판단이 쉬워진다.

**⑤ 텔레그램 경로는 남겨둘 것.**
어드민이 죽어도 텔레그램으로 지시할 수 있어야 한다. 두 경로가 **같은 함수**(`hermes.run`)를
타므로 어느 쪽에서 눌러도 동작이 같다 — 이 구조를 깨지 말 것(2026-08-20 개발AI 콘솔이
이미 이 원칙으로 만들어졌다).

## 8. 결정 (2026-08-27 사장 확정)

1. **`codex-shorts` 는 그냥 둔다** — 흡수하지 않는다. 별도 파이프라인으로 유지.
2. **"영상" 은 쇼츠와 분리**한다 — i2v(Wan 2.2)가 편당 250~566원이라 비용 성격이 다르다.
   탭을 나눠 실수로 비싼 걸 돌리는 일을 막는다. → 입력 탭은 **4개**(홈페이지·쇼츠·영상·개발).
3. **이번에는 1~2단계까지.** 3·4단계(결과 목록·세부 보기)는 이후.

### 확정된 탭 구성

```
시스템 > 🐮 허드 AI
├─ [홈페이지]  [쇼츠]  [영상]  [개발]     ← 1~2단계 (이번)
└─ [결과]                                  ← 3~4단계 (이후)
```

기존 메뉴 처리:
- `devai` 개발AI 콘솔 → **흡수**(= 개발 탭)
- `homepage-maker` 홈페이지 생성 → **흡수**(= 홈페이지 탭)
- `homepage-reqs`(회원 신청) · `shorts`(업로드 승인) · `codex-shorts` → **유지**

## 9. 1~2단계 구현 결과 (2026-08-27 Codex)

- 홈페이지·쇼츠·영상은 종류별 입력을 받아 Developer에게 갈 실제 명세를 화면에 표시한다.
- 개발은 기존 `DevAiPanel`을 그대로 재사용한다.
- 각 제작 탭은 **명세 저장**과 **허드 시작**을 분리했다. 입력·미리보기·저장만으로는 AI를
  호출하지 않으며, 시작 버튼과 확인창을 거쳐야 `/start`가 호출된다.
- 리뷰 토글, 예상 시간·비용 안내, 수정 금지 파일·경로를 명세에 포함한다.
- 홈페이지·영상은 `ai_mp`, 쇼츠는 `shorts-factory`를 작업 경로로 고정한다.
- 기존 동시 실행 1건 제한과 승인 큐를 재사용한다. 외부 발행·운영 배포·DNS는 자동화하지 않았다.
- 3~4단계인 결과 목록, 이미지·사양서·리뷰 기록, 소스 다운로드는 아직 남아 있다.
