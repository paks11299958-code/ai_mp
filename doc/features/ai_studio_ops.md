## 0. 진단 — 무서운 게 당연하다 (실측 2026-08-08)

**실력 문제가 아니라 구조 문제다.** 지금 서버3은 이렇게 돼 있다.

★**진단 정정(조사 중 발견)**: "백업이 없다"는 **틀렸다.** 매일 06:00 자동 스냅샷
정책(`default-schedule-1`, 14일 보관)이 **이미 걸려 있었다.** 진짜 문제는 따로였다 —
**작업 직전에 뜰 방법이 없었던 것.**
- 서버3은 Spot이라 대부분 꺼져 있다 → **06:00에 안 켜져 있으면 그날치가 아예 없다.**
- 있어도 "오늘 아침" 상태다 → 오전에 설치한 걸 오후에 깨뜨리면 **못 돌아간다.**
- 실제로 오늘 FaceID 설치(14:0x)는 그날 스냅샷(06:45)에 **없었다.**
→ **`snapshot` 명령 신설로 해결**(§2). 자동은 그대로 두고 수동을 더한 것이다.

| 항목 | 현재 | 문제 |
|---|---|---|
| 되돌리기 | 자동 06:00만 | **작업 직전 시점으로는 못 돌아감** → ✅해결 |
| ComfyUI 버전 | `6f7cd7f`(08-05) **고정 안 됨** | `git pull` 한 번에 전부 갱신 |
| 파이썬 패키지 | 고정 없음 | 오늘 insightface 설치가 onnxruntime을 덮어써 CUDA가 죽었다 |
| 모델 | **54GB / 6개 체크포인트** | 실제 쓰는 건 2~3개. flux-schnell 16GB는 미사용 |
| 검증 | 매번 수작업 | "됐는지" 확인에 반나절 |
| 산출물 | output 57개 방치 | 어느 게 뭔지 모름 |

★**오늘 하루가 이 구조의 증거다.** insightface 설치 → CPU판 onnxruntime이 GPU판을 덮음
→ opencv가 libGL 못 찾음 → 되돌릴 방법이 없어 하나씩 손으로 복구. **스냅샷 하나면
1분에 끝났을 일이다.**

## 1. 방향 — 세 층으로 나눈다

문제가 섞여 있어서 어렵게 느껴진다. 실제로는 성격이 다른 세 가지다.

```
①  못 깨지게 만들기      ← 지금 가장 급함. 이게 되면 나머지가 쉬워진다
②  쏟아지는 모델 따라가기  ← 전부 좇지 않는다. 걸러내는 기준을 만든다
③  검증을 자동화하기      ← "됐는지"를 반나절 말고 10분에
```

## 2. ①안 깨지게 — **스냅샷** ✅ **2026-08-08 구현 완료**

**핵심: 되돌릴 수 있으면 안 무섭다.**

```sh
cd ~/rag
./ai_studio_ctl.sh snapshot faceid-test   # ★위험한 작업 전에 이 한 줄
./ai_studio_ctl.sh snapshot-list          # 최신순 목록
./ai_studio_ctl.sh snapshot-restore <이름> # 복원 절차 안내(실행은 사람이)
```

**실측 검증(2026-08-08)**: `ai-studio-manual-20260807-151739-faceid-done` 생성 성공.
크기 **5.66GB** — 오늘 설치한 FaceID 자산(ipadapter 2.2G + insightface 0.6G +
loras 0.36G)과 산출물이 실제로 담겼다는 뜻. **증분도 정상 작동**
(전체 69.5GB → 다음날 0.83GB → 오늘 5.66GB).

**★언제 뜨나 — 이때는 반드시**
- pip 설치 / 커스텀노드 추가 / ComfyUI 업데이트 **직전**
- 새 모델 실험 전
- ★오늘 같은 사고(insightface 설치가 onnxruntime을 덮어 CUDA가 죽음) 때
  스냅샷이 있었으면 1분에 복구됐다.

**★restore를 일부러 자동화하지 않은 이유**
복원은 **되돌릴 수 없다**. 인스턴스 정지 → 디스크 분리 → 스냅샷으로 새 디스크 생성 →
재부착의 4단계인데, 중간에 실패하면 **부팅 디스크 없는 상태로 남는다.**
버튼 한 번에 걸 성격이 아니고, 어드민 API가 뚫리면 곧바로 서버3 파괴로 이어진다.
→ **절차만 출력하고 사람이 직접 실행**한다(§ctl.sh `snapshot-restore`).

**비용**: 증분이라 54GB 전체가 아니라 바뀐 만큼만. 자동 정책은 14일 보관.
수동 스냅샷은 자동 삭제되지 않으므로 **가끔 오래된 것을 정리**할 것.

**+ 함께 할 것 (각 10분)**
- `pip freeze > ~/pip_freeze_YYYYMMDD.txt` — 지금 상태를 글로 남긴다.
  오늘 같은 패키지 사고 때 "무엇이 달라졌나"를 알 수 있다.
- ComfyUI 커밋 고정 기록 — 지금 `6f7cd7f`. ★**`git pull` 금지**를 명문화.
  올릴 땐 스냅샷 뜨고 올린다.

## 3. ②모델 따라가기 — **전부 좇지 않는다**

★**따라가려 하면 진다.** 매주 새 모델이 나온다. 대신 **거르는 기준**을 만든다.

### 3-1. 우리 기준 (이걸 통과 못 하면 안 본다)
1. **상업 이용 가능한가** — Apache 2.0 / MIT 등. ★`flux1-dev`는 **비상업**이라
   고객 결과물에 못 쓴다(내부 검토용). 라이선스가 첫 관문이다.
2. **L4 24GB에 올라가는가** — 안 올라가면 우리에겐 없는 모델이다.
3. **우리 용도에 해당하는가** — 아래 3-2의 빈칸을 메우는가.
4. **기존보다 나은가** — ★**감이 아니라 A/B로.** 오늘 얻은 교훈:
   "된다"와 "기존보다 낫다"는 다르다.

### 3-2. 용도 표 (빈칸이 곧 "찾을 것", 채워진 칸은 "이미 됨")

| 용도 | 현재 | 상태 |
|---|---|---|
| 인물 실사 | RealVisXL_V5 | ✅ |
| 사물·공간 | JuggernautXL_v9 | ✅ |
| 일러스트 | sd_xl_base_1.0 | ✅ |
| 확대 | 4x-UltraSharp | ✅ |
| 얼굴 정체성(회원 본인) | **Gemini API** | ✅ (FaceID 실측 후 API 유지) |
| 같은 인물 반복 | IPAdapter FaceID | 🔶 구축됨, 상품 미정 |
| **동영상** | **Wan 2.2 TI2V-5B** | ✅ 2026-08-08 채움(착수 대기) |
| 한글 텍스트 렌더 | gpt-image-2 API | ✅ |

★**"새 모델이 나왔다"가 아니라 "이 표의 빈칸이 메워지나"로 본다.**
~~지금 가장 값어치 있는 건 **동영상**이다~~ → **2026-08-08 메웠다.** LTX·Wan 실측 후
**Wan 2.2 TI2V-5B(i2v)** 채택(5초 7.1분/44원, Apache 2.0, 원본급 화질).
상세는 `video_model_research.md`, 활용처는 메모리 `project_todo`.
★**14B는 L4로 불가**(45분+ 미완) — 병목이 GPU가 아니라 **시스템 RAM**(15GB 중 424MB)이었다.
★**A100 쿼터 신청은 거부**됐고, 순서를 바꿨다 — **5B로 상품에 먼저 넣고** 병목이 생기면 신청.

### 3-2-1. 검토 이력 — 기준을 실제로 적용한 사례

**같은 모델을 두 번 조사하지 않기 위해 판정 결과를 남긴다.**
"안 쓰기로 했다"보다 **"왜 안 쓰는지"**가 중요하다 — 조건이 바뀌면 결론도 바뀐다.

| 모델 | 판정 | 핵심 사유 | 날짜 |
|---|---|---|---|
| **Wan 2.2 TI2V-5B** | ✅ **채택** | i2v 원본급 화질·Apache 2.0·5초 7.1분/44원 | 2026-08-08 |
| Wan 2.2 I2V **14B** | ❌ L4로 불가 | 45분+ 미완. ★병목은 GPU가 아니라 **RAM**(15GB 중 424MB) | 2026-08-08 |
| LTX-Video 0.9.5 (2B) | 🔶 보류 | 빠르지만(4.2분) Wan보다 화질이 뭉갬. ★t2v는 뿌옇게 나와 쓰기 어려움 | 2026-08-08 |
| `moodyKrea2Mix_v60` | ❌ **도입 안 함** | 4개 기준 중 3개 탈락(아래) | 2026-08-08 |
| `flux1-dev` | ❌ 미설치 | **비상업 라이선스** — 고객 결과물에 못 씀 | 2026-08-05 |
| `flux1-schnell` | ❌ 삭제 | 상업가능하나 "사람 사진은 RealVis가 나았다" | 2026-08-08 |
| IPAdapter FaceID | 🔶 구축했으나 프로필사진엔 미채택 | 정체성은 Gemini 우세. 신규기능용으로 재배치 | 2026-08-08 |

#### moodyKrea2Mix_v60 상세 (사장 문의로 조사)
Civitai `Moody Krea 2 Mix (uncensored)` v6.0. **Krea 2** 기반 체크포인트 병합.

| 기준 | 판정 | 근거 |
|---|---|---|
| ①라이선스 | ⚠️ 조건부 + **부적합** | 연매출 $1M·50인 미만만 무료. ★**`(uncensored)` 버전**이라 일반 회원 서비스에 부적합하고, 라이선스가 **콘텐츠 필터링 구현을 의무화**한다 |
| ②VRAM | ⚠️ 빠듯 | FP8 기준 transformer 12.01GiB + **text encoder 4.88GiB**(Qwen3VL-4B) + VAE 0.24GiB = **약 17.1GiB**. RTX 4090(24G)에선 여유롭다지만 **L4는 같은 24GB라도 대역폭·연산이 낮고**, 우리 서버엔 IPAdapter·insightface가 함께 올라간다 |
| ③용도표 빈칸 | ❌ 안 메움 | 우리 빈칸은 **동영상**인데 이건 또 하나의 이미지 모델. 인물 실사는 RealVisXL이 이미 담당 |
| ④기존보다 나은가 | ❌ 미검증+부작용 | ★**Krea 2는 SDXL이 아니다**(12.9B 독자 DiT). → **IPAdapter FaceID가 안 붙고**(SDXL 전용), `gpu_worker.py` 워크플로를 새로 짜야 하며, 기존 LoRA·ControlNet 자산도 호환 안 됨 |

★**Flux 검토 때와 똑같은 함정** — "모델만 바꾸면 됨"이 아니다. 아키텍처가 다르면
**주변 자산(FaceID·LoRA·ControlNet·워크플로)이 통째로 무효**가 된다. 새 모델을 볼 때
**"이게 우리 기존 자산과 같은 계열인가"를 가장 먼저** 확인할 것.

**참고**: `FLUX.1-Krea-dev`도 있으나 **비상업 라이선스**라 고객 결과물엔 못 쓴다
(flux1-dev를 안 받은 것과 같은 이유).
