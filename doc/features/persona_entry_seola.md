## v9 제작과 미디어 계약

실사 사진 판과 CG 공을 합성한 8.5초·30fps 인트로를 히어로 배경에서 재생한다. S1 2초 준비 → S2 1.5초 임팩트 → S3 2.5초 직선 접근·짧은 립 흔들림·단계적 낙하 → S4 2.5초 미소 순서다. S1 데스크톱은 1920×1080/30fps Blender 카드 재렌더, 모바일은1080×1920/30fps 원본 사진 카드 재투영이며 저해상도 미리보기 반복이 아니다. 원본 사진 자체의 크기는1664×936/941×1672다.

Veo만으로 정확한 퍼팅 접촉·공 크기·연속 샤프트·홀 가림을 재현하기 어려웠다. 인물과 잔디는 사진 판을 유지하고, 퍼터 중간 위치는 제한된 사진 마스크로 합성하며, 공의42.7mm/홀108mm 비율·낙하 가림·그림자는 CG로 제어했다. 임팩트와 공 출발의1프레임 정렬, S3 립 체류0.4초 이내가 최종 검수 기준이다.

웹 전달은1280×720/720×1280 H.264 High·yuv420p·faststart·무음이다. S1에만 HyperFrames로 임베드한 Pretendard 한글 칩3개를 합성한다. 총괄의 한도 지시에 따라 어깨 선/머리 원/진자 호/S3 퍼팅 라인은 이번 산출에서 생략했다. S4 웹 전달에서 얼굴·전신을 보호하고 주변 배경을 부드럽게 처리했다. 마지막0.5초는 같은 인코딩 프레임을 반복하며 끝 WebP는 영상 마지막 디코딩 프레임과 완전히 동일한 lossless 이미지다.

기존 v3~v8 자산은 캐시된 번들의404 방지를 위해 모두 보존한다. 아래 v7/v8 규칙은 과거 제작 결정의 기록이며 현재 인트로 타이밍을 뜻하지 않는다.

## ★퍼팅 프레임 제작 규칙 (2026-09-18 v7 — 두 번 갈아엎고 얻은 결론)

### 1) 프레임마다 따로 생성하지 말 것 — 판 하나에서 합성한다

v5는 어드레스·백스윙·팔로스루를 **장마다 따로 생성**해서 프레임이 바뀔 때 얼굴·상체·
발 위치·배경 산능선까지 달라졌다("다른 사람으로 번쩍 바뀐다"). 프롬프트로는 못 고친다.

v6부터의 제작 방식:

1. 어드레스 이미지 **한 장을 판(plate)으로 고정**한다.
2. 그 판을 **첨부**해 `gemini-3.1-flash-image`(Vertex, `location=global`)로 팔·손·어깨·
   퍼터만 바뀐 변형본을 만든다.
3. 변형본을 **머리·신발 박스 기준 정수 픽셀 정렬**(SSD 최소 탐색) 후 상체~퍼터 영역만
   **깃털 마스크로 합성**한다. 신발은 마스크에서 빼 판 픽셀을 강제한다.
4. 결과: 얼굴·머리·다리·발·배경은 판의 픽셀 **그대로**. 사람이 이동할 수 없다.

### 2) ★카메라는 퍼팅 라인 **위**(홀 뒤)에 둔다 — 옆에 두면 조준이 깨진다

생성 모델은 퍼터 헤드를 **언제나 넓적하게 정면으로** 그린다. 이는 카메라가 퍼팅 라인
위에 있을 때만 옳은 그림이다.

| 카메라 위치 | 퍼터 헤드가 보여야 하는 모양 | 모델이 그리는 모양 |
|---|---|---|
| 라인 **옆**(정면 촬영) | 짧게 옆면(포어쇼트닝) | 넓적하게 정면 → **틀림** |
| 라인 **위**(홀 뒤) | 넓적하게 정면 | 넓적하게 정면 → **맞음** |

v5~v6은 라인 옆 구도라 페이스가 홀이 아니라 카메라를 봤다. "헤드를 90도 돌려라"는
어떤 프롬프트로도 먹지 않았다(5장 전부 실패). **모델을 고치는 대신 구도를 모델에
맞췄다** — 카메라를 홀 뒤 잔디 높이에 두고 그녀를 마주보게 한 v7에서 해결됐다.
★이 구도를 라인 옆으로 되돌리지 말 것.

### 3) 프롬프트는 "방향"이 아니라 "위치"로 쓴다

"뒤로 빼라 / 오른쪽으로 옮겨라"는 무시되거나 풀스윙이 된다.
"퍼터 헤드가 **손 바로 밑 잔디에** 놓이게 하라(그래서 샤프트가 수직이 된다)"는 통한다.

### 4) 공은 원근대로 커진다

v7은 홀이 카메라에 훨씬 가깝다. 실제 홀 지름(108mm)과 공 지름(43mm)의 픽셀비로 계산해
공이 굴러오며 **데스크톱 ×4.8, 모바일 ×6.5**로 커지도록 Blender 키프레임에 넣었다.
안 넣으면 공이 홀보다 작은 채로 빨려 들어가 어색하다.

### 5) 모바일 판에는 공이 그려져 있다

모바일 어드레스 판은 생성 단계에서 공이 퍼터 페이스에 이미 그려졌다. 그래서
임팩트 이후 프레임(`thru`·`follow`)은 "공은 이미 맞아 굴러갔다"로 생성해 공이 없고,
Blender 공 레이어는 모바일에서 **임팩트 전까지 투명**이다. 데스크톱 영상도 같은
임팩트 시점부터 공과 접지 그림자를 표시한다.

### 6) v8은 브라우저 레이어가 아니라 완성 MP4를 재생한다

v7의 `<picture>` 네 장과 CSS 공 애니메이션은 브라우저 렌더 시 프레임 전환이 도드라졌다.
v8은 Blender VSE에서 5초·30fps H.264로 미리 렌더한다. 공의 직선 궤적, 감속, 회전,
접지 그림자와 홀 진입이 모두 영상 프레임 안에 들어가므로 브라우저 성능과 무관하게 같다.
데스크톱은 1672×936, 모바일은 942×1674의 별도 MP4를 `<video>`의 미디어 소스로 고른다.

### 7) 구자산은 일부러 남겨 둔다

`putt-*-v3/v4/v5.png`, `putt-*-v6.webp`는 참조가 끊겼지만 **지우지 않았다.**
옛 번들을 캐시한 브라우저가 이미지 404를 내지 않게 하기 위해서다.

## 동작 계약

- `내 스윙 점검하기`, `스윙 분석 시작` → `onFeature('swing')`로 기존 업로드·분석 화면을 연다.
- `오늘의 코스 찾기`, `코스 찾아보기` → `onFeature('golf-course')`로 기존 골프장 탐색 화면을 연다.
- `설아와 대화하기` → `onStart()`로 기존 채팅에 들어간다.
- 닫기와 `Escape` → `onClose()`로 원래 화면에 돌아간다.
- 새 API·DB·과금 경로를 만들지 않는다.

## 화면과 접근성

- 별도 게임 모달 없이 포스터를 즉시 표시하고 히어로 배경 `<video autoPlay muted playsInline preload="auto">`를 재생한다. 모바일/데스크톱 소스와 포스터·끝 이미지를 각각 제공한다.
- 카피와3개 CTA는 처음부터 보인다. 모바일 영상 영역은57svh이며390×844 첫 화면에서3개 버튼이 보인다. 데스크톱 카피는 왼쪽, 인물은 오른쪽이다. 태블릿은 데스크톱 소스의 오른쪽 구도를 쓰고 CTA는 아래에 배치한다.
- 우상단 건너뛰기/영상 종료는 끝 이미지로 전환한다. 다시 보기로 재생할 수 있다. 자동재생 거부·영상 로드 실패는 포스터와 기능 버튼을 유지한다. 소스 선택 중 AbortError는 재생 실패로 오인하지 않는다.
- prefers-reduced-motion에서는 영상 없이 끝 정지만 표시한다. 닫기/Escape·기존 기능 콜백을 유지한다.
- 아래 CHOOSE YOUR ROUND와 예시 코칭 노트의 내용·동작은 유지한다. 예시 수치가 실제 분석 결과를 뜻하지 않으며 영상은 명시적인 분석 시작 전 처리되지 않는다.
