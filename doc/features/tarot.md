## 카드 뽑기 흐름 단순화 (2026-07-21, 사장 지시)

기존엔 카드 1장 뽑을 때마다 개별 해석을 요청+대기(3회)한 뒤 종합 리딩(1회)까지 AI 호출 **4회**가 발생 — 사장이 실제 카드섞기 화면을 보고 "3장 한번에 뽑고 결과도 한번에" 제안, 절충안으로 확정:
- **카드 뽑기는 대기 없이 연속 진행**(부채꼴 클릭하는 재미는 유지) — `TarotCardModal.tsx`의 `pick()`이 매번 채팅 전송하지 않고 `drawn`에만 쌓음.
- **AI 호출은 3장 다 뽑은 뒤 종합 1회만** — `askSummary()`가 3장 정보를 전부 프롬프트에 담아 한 번에 전송. 개별 해석 요청(`askYuna`)은 제거.
- `mode='daily'`(오늘의 카드 1장)는 원래도 1장+즉시 해석 구조라 변경 없음.
- 채팅 메시지 전송 1건=일일 무료 한도 1회 소모(위 "과금" 참고)라, AI호출 4→1회로 사용자의 무료 대화 소모도 그만큼 감소.

## 리딩 보고서 (바이럴 장치)

## 효과음 추가 (2026-07-29, 사장 제안)

타로는 원래 **손맛과 소리로 기억되는 행위**인데 셔플·플립 애니메이션만 있고 무음이라
체감의 절반만 전달되고 있었다. 카드 3구간에 효과음을 넣었다.

| 시점 | 파일 | 볼륨 |
|------|------|------|
| "✨ 카드 섞기" 클릭 → 셔플 애니메이션(1.4초) | `tarot-shuffle.mp3` | 0.3 |
| 카드 1장 선택(3회 반복) | `tarot-flip.mp3` | 0.3 |
| 3장 공개 완료 | `tarot-reveal.mp3` | 0.25 (320ms 지연) |

- 음원은 **CC0**(퍼블릭 도메인). 출처·가공 명령어는 `public/sounds/CREDITS.md`.
  후보 7종을 사장이 **직접 들어보고** 선택(셔플 B / 뽑기 B / 차임 A) — ★소리·로고 같은
  감각 자산은 글자 설명으로 고르게 하지 말 것.
- 합계 41KB(모노 44.1kHz 96kbps, -20 LUFS 정규화). 후보마다 음량이 제각각이었고
  최대 0.0dB로 클리핑 위험인 것도 있어, 정규화해야 재생 볼륨을 코드 한 곳에서 통제할 수 있다.

**구현**: `frontend/utils/sound.ts`(공통 유틸) → `TarotCardModal.tsx`에서 호출.
- ★**재생 시작점이 "카드 섞기" 클릭**이라 모바일 자동재생 차단에 안 걸린다 — 이 모달의
  첫 사용자 조작이기 때문. 인트로에서 자동으로 울리게 했으면 차단됐다.
- **재생 실패는 삼킨다**(`play().catch(()=>{})`) — 소리는 부가 요소인데 예외가 올라가면
  정작 카드 뽑기 로직이 멈춘다.
- **차임은 320ms 지연** — 뽑기 소리와 동시에 울리면 둘 다 뭉개져 들린다.
- 모달 헤더에 **🔊 토글**(기본 켬, 사장 결정) + `localStorage['ui_sound_muted']` 기억.
  지하철·사무실에서 바로 끌 수 있어야 한다.
- 볼륨·음소거를 유틸 한 곳에 모은 이유: 기능마다 흩어지면 "어떤 화면은 나고 어떤 화면은
  안 나는" 상태가 되고, 나중에 전역 음소거를 넣을 때 반드시 누락이 생긴다.

**검증**(운영 URL 실측): 재생 5건(shuffle 1 + flip 3 + reveal 1) 볼륨까지 확인,
음소거 시 **완전 차단**·새로고침 후 유지 확인, 음원 3개 200 `audio/mpeg` 서빙 확인.
