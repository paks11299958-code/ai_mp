## 단계별 계획과 통과 기준

### 2단계 — 전수평가와 최초 5개 선정

Community 후보를 상업성, 업종 적합성, 모바일, 자립형 배포, 외부 의존성,
압축 전송량, 테마 변경 가능성으로 평가한다. `사용 가능 / 수정 후 가능 / 제외`로 분류하고
AI·IT, 뷰티·패션, 카페·요식업, 부동산·건축, 일반기업용 각 1개를 선정한다.

### 3단계 — 독립 데모 갤러리

`sites/` 아래 운영 생성기와 분리된 데모로 만든다. PC와 모바일, 애니메이션 감소,
WebGL 실패 대체 화면, 화면 밖 렌더 중지를 Playwright로 확인한다. 사장 확인 전 운영 생성기에
연결하지 않는다.

### 4단계 — manifest 기반 생성기 연결

manifest에는 컴포넌트 ID, 추천 업종, 위치, 허용 테마 변수, 자산 목록·크기,
모바일 모드, 대체 이미지, 라이선스를 기록한다. 기획 단계는 ID와 테마 값만 선택하고,
조립 단계가 검증된 코드와 자산을 복사한다. 홈페이지당 WebGL 캔버스는 최대 1개다.

### 5단계 — 신청 화면과 어드민 베타

신청서에 `없음 / 은은함 / 강함`을 추가하되 기본 정책은 2단계 결과로 결정한다.
어드민 생성과 샘플부터 열고 회원 생성에는 아직 적용하지 않는다.

### 6단계 — 정식 범위 확정

실사용 로딩, 브라우저 오류, 모바일 프레임, 이탈 흐름을 검토해 허용 컴포넌트와
기본값을 확정한다. 성능 기준 미달 후보는 2D 대체 화면으로 강등하거나 제외한다.

## 운영 안전 기준

- 홈페이지당 ThreeUI/WebGL 컴포넌트 최대 1개.
- 글자·CTA는 DOM으로 유지하고 캔버스가 클릭·가독성을 방해하지 않아야 한다.
- `prefers-reduced-motion`, WebGL 미지원 대체 화면, 모바일 정지/경량 모드 필수.
- 화면 밖에서는 렌더 루프를 중단하고 제거 시 GPU 자원을 해제한다.
- 원격 이미지·영상에 의존하지 않는 자립형 `source.zip`을 제공한다.
- 콘솔 오류·요청 실패·누락 자산 0건, 기존 `audit_html` 통과 전에는 배포하지 않는다.

## 3단계 독립 데모 결과 (2026-08-23)

- `/sites/threeui-lab/`에 5종 비교 연구실을 만들고 PC·390px 모바일에서 각각 렌더를 확인했다.

- DPR은 1.5로 제한하고 모바일 입자/도형 밀도를 줄였다.
- 갤러리 초기 JS는 약 201KB, 전체 갤러리는 약 744KB다. 큰 Orbital 원본 청크가 약 505KB지만,
  운영 어댑터는 React/Three 번들을 복사하지 않고 선택된 2D Canvas 런타임만 인라인한다.

## 4단계 생성기 어댑터 결과 (2026-08-23)

- 정본 manifest: `~/rag/threeui_catalog.json` — 원본 커밋, 라이선스, 업종 키워드, 위치,
  모바일 모드, 대체 방식, 허용 테마, 렌더러를 기록한다.
- 검증 런타임: `~/rag/threeui_runtime.js` — 외부 의존 없는 단일 Canvas 모듈이며 5개 ID만 지원한다.
- `homepage_worker.py`는 `HOMEPAGE_THREEUI_BETA=1`이고 신청값이 `soft` 또는 `strong`일 때만
  효과를 고른다. ID 직접 요청도 manifest 화이트리스트 밖이면 거부한다.
- 조립 모델은 마운트 요소만 만들고 효과 코드를 작성하지 않는다. 워커가 정확히 한 개의 마운트를
  확인한 뒤 로컬 런타임을 삽입하며, 계약 위반 시 기존 재생성 경로로 보낸다.
- 회원 요청은 기본 `none`, 환경 플래그도 기본 OFF라 기존 생성에는 변화가 없다.

## 5단계 관리자 베타 준비 (2026-08-23)

- 홈페이지 신청 화면에 관리자에게만 `없음 / 은은함 / 강함` 선택을 표시한다.
- API는 일반 회원이 요청 본문을 변조해도 ThreeUI 값을 제거하고, 관리자의 세 값만 허용한다.
- 서버2 홈페이지 워커 크론 한 줄에만 `HOMEPAGE_THREEUI_BETA=1`을 적용했다. 관리자 요청만
  효과값을 보존하므로 회원 생성은 계속 기존 동작이며, 관리자 실제 생성본부터 관찰한다.

### 개발AI 콘솔 연결

- 개발AI 콘솔의 `홈페이지 요구사항` 안에 `사용 안 함 / 자동 추천 / 직접 선택`과
  `은은함 / 강함`을 추가했다. 기본값은 `사용 안 함`이다.
- 옵션은 기존 요구사항 JSON에 버전별로 저장하므로 DB 마이그레이션이 없고 과거 프로젝트와 호환된다.
- `자동 추천`은 서버2가 manifest의 업종 키워드로 ID 하나를 확정하고, `직접 선택`은 5개 허용 ID만
  저장·전달한다. 브라우저, shared-api, 서버2에서 각각 다시 검증한다.
- Hermes에는 선택된 ID와 강도, 고정 원본 커밋, 로컬 manifest·런타임 경로만 전달한다.
  임의 Three.js/WebGL 작성, iframe, 외부 CDN, canvas 중첩은 금지한다.
- 신규 독립사이트·랜딩 페이지의 히어로에만 적용한다. 어드민 본체·대시보드·로그인·결제 작업이면
  적용하지 않고 제외 사유를 결과에 남긴다.
