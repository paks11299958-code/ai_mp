# 로그인·회원가입·비밀번호 찾기 화면 (2026-10-05 개편)

ai_mp `438f003` + shared-api `255c214`. 시안·조사·검수 자료 = `~/design-lab/auth-redesign/`(research·round0 1안/2안·round1).

## 왜
사장 지시 "로그인과 가입 버튼 배치·설명이 확실히 구분되고 쉽게". 운영 점검(비로그인 캡처)에서:
첫 화면에 로그인/가입 버튼 없음(⭐·☰ 뿐) · 이름 3종 혼재(AI 놀이터/AI 페르소나/옛 랜딩 "AI PERSONA Chat") · 로그인/가입 탭 + 가입 방식 2차 탭 · 가입 탭에도 "카카오 로그인" · 🔴**가입 시 약관·개인정보 동의 0건**.

## 구조 (1안 "화면 분리형" — 사장 선택)
| 화면 | 주 버튼 | 반대편 |
|---|---|---|
| 비로그인 머리말·☰ | 회원가입(보라) / 로그인(연한) | — |
| 로그인 | 로그인하기 | 처음 오셨나요? 회원가입하기 · 비밀번호 찾기 · 카카오 로그인 |
| 회원가입 1/2 | 인증번호 받기(필수 동의 전 잠김) | 이미 회원이신가요? 로그인하기 |
| 회원가입 2/2 | 회원가입 완료하기 | 가입 정보 수정 · 재전송 01:00 |
| 비밀번호 찾기 | 휴대전화=인증번호 받기 / 이메일=재설정 링크 받기 | 로그인으로 돌아가기 |
| 재설정 `?token=` | 비밀번호 변경하기 → 로그인으로 돌아가기 | (옛 `LandingPageNew` 배경 제거) |
| 체험→정식가입 | 인증번호 받기(동의 포함) | 체험으로 돌아가기 — 충전 층 z-9000 portal 유지 |

- 진입: `useAuth.openAuthPage('login'|'register')`. 기존 `goTo('authPage')` 는 로그인 고정(호환).
- 동의: `ConsentFields.tsx`(전체 동의·[필수] 이용약관·개인정보 수집·이용·만 14세, 보기=`TermsModal`, 보기 후 입력·체크 유지) → `verifyRegister`/`upgradeGuest` 에 `consent` 전달 → 서버 `"UserConsent"` 기록. 카카오 신규는 `kakao_login.md` 참고.
- 서버 호환: consent 없는 옛 요청도 **가입 허용**(경고 로그만), 잘못된 값만 400 — 배포 순서가 어긋나도 가입 장애 0.

## 함정·남은 것
- 약관 본문을 바꾸면 shared-api `lib/consent.ts` `CONSENT_VERSION` 을 올린다.
- 새 인증 컴포넌트(`AuthModal`·`RegistrationForm` 등) 일부가 한 줄 600자+로 압축돼 있다 — 프로젝트에 포매터가 없어 정리 보류(동작 무관).
- 실가입·실 SMS/메일·카카오 OAuth E2E 는 배포 검수에서 미실행(부작용). 첫 실가입 후 `select * from "UserConsent"` 로 확인.
