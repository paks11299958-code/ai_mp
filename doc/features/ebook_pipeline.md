# 전자책 자동 출판 파이프라인 (강지훈 페르소나)

> 상태: **프로세스 재정의 완료** (2026-06-10). 기존 구현(3AI 비교·챕터별 수동 자료수집·그림자리 이미지 업로드)을 **걷어내고 아래 8탭 프로세스로 교체** 예정.
> 강지훈 페르소나: `id = writer` (작가 컨셉)
> 이전 계획(2026-06-07)은 git 이력 참조. 이 문서가 현재 기준선.

## 목표
강지훈의 "📖 전자책 만들기"에서 **탭을 순서대로 진행**하며 한 권을 완성:
제목 → 목차 → (수정) → 자료 일괄수집(새벽 배치) → 초안 PDF → 완성본 PDF(표지+북크크 양식) → 사용자가 북크크에 수동 등록.

## 전체 흐름 — 8탭 (탭을 순서대로 진행하는 UI)

```
[탭1] 제목 정하기
       └ 사용자가 책 제목 입력(또는 AI 추천)

[탭2] 목차 생성
       └ 확정된 제목 기반으로 AI가 목차 생성

[탭3] 목차 수정
       └ 제목/목차 수정 + 챕터 순서 변경 가능

[탭4] 자료 일괄 수집  ★예약 배치
       └ "자료 일괄 수집" 클릭 → 배치 시간 선택(새벽 1~5시 중 택1)
       └ 그 시각에 cron이 전체 챕터 자료를 한 번에 수집(Vertex grounding)
       └ 진행상황/완료 알림(메일). 비용·부하 새벽 분산

[탭5] 초안 만들기  ★PDF 산출
       └ 자료수집 완료 후 "초안 만들기" 클릭
       └ 클로드(서버1 CLI 구독)가 전체 챕터 본문 생성
       └ 서버(puppeteer)가 PDF 변환 — 폰트 크기 설정 적용:
            ① 큰 제목  ② 중간 제목  ③ 본문   (사용자가 크기 지정)
       └ 결과: 초안 PDF 파일 다운로드

[탭6] 완성본 만들기  ★최종 PDF
       └ 사용자가 (탭5 PDF를 직접 다듬어) 수정한 PDF를 재첨부 업로드
       └ 책 표지 생성: 책 사이즈에 꽉 차게(판형 규격)
       └ 북크크 양식 적용: 사용자가 올린 북크크 샘플 PDF/이미지 규격에 맞춰 자동 구성
       └ 결과: 최종본 PDF 다운로드

[탭7] 북크크 등록 (사용자 수동)
       └ 다운받은 최종 PDF를 사용자가 직접 북크크에 등록(자동화 아님)

[탭8] = 위 1~6을 탭으로 순서대로 진행하는 UI 자체
```

## 확정 결정사항 (2026-06-10)

- **PDF 생성 방식**: 클로드 = 본문 텍스트(마크다운) 생성 / **서버(puppeteer)** = HTML+CSS로 폰트 크기 적용해 PDF 변환.
  (클로드 CLI는 PDF 바이너리를 직접 못 만듦 → 서버 변환 필수)
- **폰트 크기 설정**: 큰제목/중간제목/본문 3단계를 사용자가 지정 → PDF CSS에 반영.
- **자료 수집 = 예약 배치**: 즉시수집 아님. 사용자가 **새벽 1~5시 중 시각 선택** → DB에 예약 → 매시 cron이 예약 작업 순회해 전체 챕터 일괄 수집. 비용·배치 부하 분산 목적.
- **기존 구현 교체**: 3개 AI 비교, 챕터별 수동 자료수집, 그림자리 이미지 업로드는 **제거**하고 새 프로세스로 재구성. (본문 생성은 클로드 단일)
- **북크크 양식**: 사용자가 **샘플 PDF/이미지 업로드** → 판형·여백·표지 규격을 그 샘플 기준으로 자동 생성.
- **북크크 등록**: 자동화 안 함(API·명의·법적 리스크). 사용자가 최종 PDF를 직접 등록. (이전 계획의 6,7 자동등록은 폐기)
- **표지**: 책 사이즈에 꽉 차게(판형 규격에 맞춤).

## ⚠️ 주의 (기존 교훈 유지)
- **데이터 구조**: 챕터는 `EbookChapter` row가 아니라 `EbookProject.tocJson`(JSON 배열). 자료/본문/상태 전부 거기 저장 → **JSON 덮어쓰는 모든 경로에서 기존 필드 보존**(과거 제목수정 시 자료 날아간 버그 있었음).
- **서버1 DB**: `prisma db push 금지`(실DB가 schema보다 앞섬) → 컬럼 추가는 raw SQL `ALTER`. snake_case는 `@map`.
- **새 보드/모달은 ErrorBoundary로 감쌈**(자식 렌더 예외가 앱 전체 크래시 방지). EbookBoard는 이미 ErrorBoundary 적용됨.
- **모바일 우선**: 탭 UI는 390폭에서 정상 동작 확인(Playwright).
- **비용**: 무료 테스트는 강지훈 본인만. 정식 오픈 전 포인트 차감 필수(자료수집·본문생성·PDF 누적).
- **클로드 본문생성**: 서버1 로컬 claude CLI 구독 인증 spawn(API키 불필요·추가비용0). shared-api가 서버1에 있어 로컬 실행이 정답.

## 기술 자산 재사용
- Vertex grounding: `shared-api/lib/gemini.ts generateChapterSources`
- 클로드 spawn: 동 파일 `generateChapterContent` claude 경로
- 메일: shared-api Brevo
- cron: 서버1 crontab(localhost:3020 internal-cron 패턴) 또는 서버2
- PDF: **puppeteer 신규 도입** (HTML→PDF, 폰트 CSS 제어)
