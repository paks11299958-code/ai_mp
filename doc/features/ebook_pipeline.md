# 전자책 자동 출판 파이프라인 (강지훈 페르소나)

> 상태: **계획 수립** (2026-06-07). 단계별로 하나씩 구현 예정.
> 강지훈 페르소나: `id = writer` (작가 컨셉, 전자책에 적합)

## 목표
강지훈 채팅의 "📖 전자책 만들기" 메뉴에서 **주제만 입력하면**, 자료수집→AI정리→책 확장→PDF→사용자 컨펌→북크크 자동등록까지 가는 자동 출판 파이프라인.

## 전체 흐름 (7단계)
1. **주제 입력 + 일배치 자료수집**: 주제 입력 → 매일 cron이 돌며 AI 웹검색(Vertex grounding)으로 자료 수집, 이메일로 진행상황 전달
2. **AI 1차 정리**: 배치가 수집 자료를 AI에 던져 1차 정리
3. **책으로 확장**: 1차 정리본을 AI가 책 분량으로 확대 정리(목차/장/절)
4. **PDF + 표지 생성**: 확대본을 북크크 규격에 맞춰 표지 만들고 PDF화
5. **메일 컨펌**: PDF를 사용자에게 메일 발송 → 사용자 확인(승인 게이트) → 1차 마무리
6. **북크크 자동등록**: 승인된 PDF를 북크크에 자동 업로드(아이디/PW 필요)
7. **등록 완료**

## 결정사항 (2026-06-07)
- **자료수집 방식**: AI 웹검색 — Gemini Vertex grounding(Google Search). 오늘뉴스(news_collector)에서 검증된 방식 재사용.
- **북크크 등록**: **공식 API/업로드 방식 먼저 조사** → 없으면 Playwright 자동화 검토(깨지기 쉬움). 맨 마지막 단계.
- **사용자별 분리**: 전자책 작업물은 `userId`로 분리(주식/명품/손금과 동일). 각자 자기 책만 조회·관리. 배치도 사용자별 활성 작업 순회.
- **범위 결정: 일단 PDF까지(1~5단계)만 사용자별로 구현. 북크크 자동출판(6,7)은 보류** — '누구 명의로 출판되나'(운영자 vs 사용자 계정)가 사업·보안·법적 결정이라 나중에. 6,7은 그때 재논의.

## ⚠️ 사용자별일 때 추가 고려 (확장 시)
- **비용**: 사용자×매일 AI 호출(자료수집+책생성) 누적 → 포인트 차감 또는 사용 제한 필요(다른 메뉴처럼).
- **배치 부하**: 사용자 많으면 매일 배치 무거움 → 순차/큐 관리.
- **북크크 계정 명의**(보류된 6,7): 운영자 1계정 = 명의·수익 운영자 / 사용자 각자계정 = 남의 비번 저장 보안·법적 리스크. 미결.

## ⚠️ 난이도/리스크 분류 (한 번에 만들지 말 것)
| 단계 | 난이도 | 비고 |
|---|---|---|
| 메뉴 추가(강지훈 quickMenuJson) | 🟢 | 손금 패턴(placeholder/모달) |
| 2,3 AI 정리/확장 | 🟢 | Gemini/Claude 프롬프트, 기존 자산 |
| 5 메일 컨펌 | 🟢 | Brevo 메일(기존) |
| 1 배치 자료수집 | 🟡 | cron + Vertex grounding. 진행상황 메일 |
| 4 PDF+표지 | 🟡 | PDF 생성(puppeteer 등) + 북크크 규격 |
| 6,7 북크크 등록 | 🔴 | API 불명·자동화 깨짐·아이디PW 보안·출판은 비가역 외부행위. **자동등록 전 사람 컨펌 필수**(5단계가 그 게이트) |

## 권장 구현 순서
1. **메뉴 + AI 정리/확장(2,3)** — 핵심 가치, 가장 쉬움. 주제→초안 책 텍스트
2. **PDF + 표지(4)** — 결과물 형태 확정
3. **메일 컨펌(5)** — 사람 검수 게이트
4. **배치 자료수집(1)** — 자동화(매일 cron, Vertex grounding)
5. **북크크 등록(6,7)** — API 조사부터, 맨 마지막

## 보안/주의
- 북크크 아이디/PW는 평문 저장 금지 → .env 또는 별도 안전 저장. (서버1 git-credentials 분리 패턴 참고)
- 북크크 자동등록은 되돌리기 어려운 출판 행위 → **반드시 5단계 사용자 승인 후에만** 실행.
- 데이터 저장: 책 작업물(주제/자료/초안/PDF)은 DB 또는 GCS. 진행상태(수집중/정리중/PDF생성/컨펌대기/등록완료) 관리 필요.

## 기술 자산 재사용
- Vertex grounding: `agent-api/news_collector.py` _build_gemini_client 패턴
- 메일: shared-api Brevo (product-extractor/monitor와 동일)
- cron: 서버2 crontab 또는 shared-api internal-cron
- 결과 보드 UI: StockAnalysisBoard(좌측 작업목록 + 우측 상세 + 진행 스텝퍼) 패턴
