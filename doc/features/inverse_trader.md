# 📈 인버스 ETF 1호가 스캘핑 (시뮬레이션 전용)

> 신설 2026-08-20 · 어드민 → 운영 → `인버스 자동매매`
> 관련: `doc/db_schema.md`(Inverse* 6모델), work_index §14 2026-08-20

## 무엇인가

인버스 ETF 1종목을 **1호가 차이로 반복 매매**하는 전략을 가상매매로 돌리고 어드민에서
상태·포지션·주문·체결·손익을 확인하는 기능.

★**시뮬레이션 전용이다.** `TRADING_MODE` 는 `'SIMULATION'` 리터럴 하나만 허용하고
`'LIVE'` 는 타입·런타임 양쪽에서 거부한다(환경변수 경로 포함). 증권사 주문 API를
import 하거나 호출하는 코드가 한 줄도 없다. 실측 검증 6/6 통과.

이 기능은 **허드 개발 파이프라인으로 만든 첫 실전 산출물**이다(4묶음·약 4,700줄).

## 전략 규칙

기본 주문수량은 설정값(투자금 기준). 호가단위는 가격대별로 계산한다.

1. 시작: 현재 최우선 매수호가 **-1호가**에 매수
2. 매수 체결 → (체결가 **+1호가**) 매도 + (체결가 **-1호가**) 추가매수 — 2건
3. 매도 체결 → (체결가 **-1호가**) 매수 + (체결가 **+1호가**) 매도 — 2건
4. 반복

부분체결을 지원한다(후속 주문 수량은 **실제 체결수량** 기준). 같은 종목·방향·가격에
살아있는 주문이 있으면 중복 생성하지 않는다.

## 당일정산 (최우선 규칙)

장 종료 N분 전(기본 10분)에 `FORCE_SETTLEMENT` 로 전환:

```
신규매수 중단 → 미체결 전부 취소 → 보유수량 0 될 때까지 매도
→ 최종 0 확인 → 손익 기록
```

이탈 조건 3종으로 무한루프를 막는다: **시도 20회 / 무진전 5회 / 60초 상한**.
시도가 거듭될수록 1호가씩 낮춰 공격적으로 걸되 **시장가는 쓰지 않는다**(대량 슬리피지 방지).
마감 후 포지션이 0이 아니면 실패로 기록하고 화면에 경고한다.

## ★호가단위 — 실측으로 정정한 결함

초기 코드는 `ETF_TICK_BANDS` 가 **"ETF는 전 가격대 5원 단일"** 이었다. **사실이 아니다.**

```
KODEX 200선물인버스2X(252670) 최근 10일 종가
78 / 88 / 79 / 76 / 81 / 87 / 94 / 96 / 97 / 96   ← 하나도 5의 배수가 아니다
```

5원 단일로 두면 저가 ETF에서 주문가가 격자에 안 맞아 **전량 거부된다.**
→ **2,000원 미만은 1원**, 그 이상은 5원.

★고가 구간은 원래 주석이 맞았다 — KODEX 레버리지(122630)는 10만원대인데 종가가
`110,465`·`113,525` 로 **5원 단위**다(주식 밴드라면 100원이어야 한다). 그래서 주식 밴드를
그대로 쓰면 안 되고 **2,000원 경계 하나만** 두는 것이 실측과 맞는다.

`SimulationBroker` 의 호가단위 검증도 고정 tick → 가격대별 조회로 바꿨다.

★**1틱의 비중이 가격대마다 다르다** — 5,000원짜리의 1틱(5원)은 0.10%인데 78원짜리의
1틱(1원)은 **1.28%** 다. 같은 "1호가 먹기"라도 저가 종목에서는 스캘핑이 아니라
변동성 베팅이 된다.

## 안전장치

| 항목 | 내용 |
|---|---|
| `TRADING_MODE` | `SIMULATION` 고정. LIVE 는 상수·환경변수 어느 경로로도 거부 |
| 최대보유수량 | 초과 예상이면 신규 매수 차단(`evaluateBuyGuard`) |
| 공매도 금지 | 보유 잔량에 맞춰 매도수량 축소(`evaluateSellGuard`) |
| **손절** | 평단 대비 하락률 초과 시 발동(`evaluateStopLoss`) |
| **물타기 제한** | 횟수·낙폭 두 기준으로 추가매수 차단(`evaluateAddBuyGuard`) |
| 일일 최대손실 | 초과 시 정지 |

손절·물타기 제한은 **백테스트에서 확인된 최대 약점**을 막기 위해 나중에 신설했다.

## 백테스트

`npx tsx scripts/inverse-trader/backtest.mts`

실제 전략 함수·브로커·리스크 가드를 **그대로 태우고** 시장 시나리오만 갈아끼운다.

**손절 없는 현행 결과: 5일 -7.1억**

| 시나리오 | 왕복 | 당일손익 |
|---|---|---|
| 횡보 | 220회 | +2.2억 |
| 완만한 상승 | **8회** | +5.0억 |
| 완만한 하락 | 38회 | -2.3억 |
| **급락** | 8회 | **-14.2억** |

**지는 이유 3가지**
1. 이길 땐 조금, 질 땐 크게 — 횡보 220왕복으로 번 2.2억을 급락 하루가 -14.2억으로 지운다
2. **스캘핑인데 회전이 안 된다** — 상승장 왕복이 8회뿐(가격이 오르면 매수가 안 걸림)
3. 손절이 없어 급락에 물량이 깔리고 마감 강제청산으로 손실이 확정된다

★**거래비용은 문제가 아니었다**(초기 우려가 틀렸다) — 토스 국내주식 수수료·세금 실측 0원 +
ETF 매도 거래세 면제라 1틱이 통째로 남는다. 실질 비용은 **청산 슬리피지**뿐.

★**백테스트 작성 중 잡은 함정 4가지**(전부 조용히 틀린 결과를 만든다):
- `SimulationBroker` 옵션은 **`feed`** — `quoteFeed` 로 주면 무시되고 랜덤 피드가 쓰인다
- `planSessionStartOrder(ctx, bidPrice, qty)` 는 **위치 인자**
- `FillRecord` 필드는 **`fillPrice`·`fillQty`** — `price`·`qty` 로 읽으면 NaN 이 번진다
- 가드를 안 태우면 공매도·무한보유로 **하루 수천억이라는 허구 수익**이 찍힌다

## ★시세 — 호가를 주는 곳은 키움뿐 (전수 실측)

| 경로 | 호가·잔량 | 확인 방법 |
|---|---|---|
| 네이버 폴링 API | ❌ 현재가만 | 직접 호출 |
| 다음 금융 | ❌ 현재가만 | 호가 요청은 500 |
| **토스 오픈API** | ❌ 현재가만 | 서버1에서 `/api/v1/prices` 실호출 — 응답이 `{symbol,timestamp,lastPrice,currency}` 뿐. 공개 엔드포인트는 prices·candles·holdings·orders·accounts 5개로 **호가창은 목록에 없다**(앱엔 보여도 API로는 안 연다) |
| **키움 REST API** | ⭕ | `ka10004` 주식호가요청 + **WebSocket `0D`(주식호가잔량) 실시간 구독** |

현재는 `NaverQuoteFeed`(현재가 → `bid=현재가, ask=현재가+1틱` 근사)가 끼워져 있다.
★**잔량을 모르므로 실제보다 체결이 후하게 난다** — 결과를 볼 때 반드시 감안할 것.

### ★저장소 사본과 서버1 사본이 둘 다 있는 이유 (2026-08-20)

API 는 서버1로 옮겼지만 `api/_lib/inverse-trader/` 와 `api/inverse-trader/engine·settlement`
는 **지우지 않았다**. 백테스트(`backtest.mts`)와 테스트(`npm run test:inverse`)가 이 경로를
직접 import 하기 때문이다 — 지웠더니 7종 테스트가 통째로 깨졌다(실측).

즉 저장소 쪽은 **전략 개선·백테스트용 라이브러리**, 서버1 쪽은 **운영 서빙용**이다.
★전략을 고치면 **양쪽 다** 반영해야 한다. 한쪽만 고치면 백테스트 결과와 운영 동작이 갈린다.
서버1로 옮길 때는 import 만 평탄화했고(`../_lib/inverse-trader/x.js` → `./x`),
검증 로직은 바이트 비교로 동일함을 확인했다.

### ★왜 서버1로 옮겼나

Vercel 서버리스는 VPC 밖이라 Postgres(내부IP `10.178.0.2`)에 붙지 못해 어드민 탭이
`Operation has timed out` 으로 멈췄다. 개발AI 콘솔과 **같은 원인**이다
(`doc/features/devai_console.md` 참고). 프런트는 `/api/admin/inverse-trader/<action>` 으로
부르고 `vercel.json` 의 `/api/admin/:path*` rewrite 가 서버1로 보낸다.

## ★남은 일

1. **전략 개선 후 재측정** — 손절·물타기 제한을 넣고 백테스트를 다시 돌려 급락 손실이
   얼마나 주는지 확인. 백테스트가 이미 있으므로 효과가 숫자로 나온다.
2. **키움 API 연결** — 모의 키 발급 후 `QuoteFeed` 구현체 추가.
3. 어드민 설정 초기값은 시드돼 있다(252670 / 투자금 1,000만원 기준 / 손절 -2% /
   물타기 10회·-3% / `enabled=false`).
