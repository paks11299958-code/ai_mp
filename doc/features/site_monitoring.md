## 설계 원칙 (★함정과 함께)

- **정상일 때도 전체 요약 발송**(사장 결정). 알림이 안 오는 게 정상인지 감시가 죽은
  건지 구분 못 하면 감시가 아니다. 정상 항목도 값을 실어 보낸다(halt 여부·발굴 기준일·
  자원 수치가 여기 있다).
- **스크린샷은 웹(site/login) 장애일 때만** 첨부. DB 이상에 사이트 화면은 단서가 없고,
  정상 보고까지 이미지면 알림이 무거워져 정작 장애를 흘려보게 된다.
- `status.json`의 `ok`는 **site+login 의미를 유지**(어드민 대시보드가 쓰는 값).
  전체 판정은 `allOk`로 분리 — 토스봇 halt 같은 다른 축의 이상을 섞으면 화면 의미가
  조용히 바뀐다.
- ★**`pgrep -f <이름>`은 쓰지 않는다** — 패턴이 **자기 명령줄에도 매칭**돼(셸·grep·
  백업 스크립트가 그 문자열을 달고 있으면) 대상이 죽어도 "살아있다"고 오판한다.
  실측: 존재하지 않는 이름을 넣었는데 3건이 검출됐다. `ps -eo pid=,args=`로 교체.
- ★**DB 계정이 컨테이너마다 다르다** — `n8n-docker-db-1`(aichat·company_wiki·n8n_db 등
  6개 DB)는 `aichat_user`, `n8n-docker-typebot-db-1`은 `postgres`. 컨테이너 기본값
  `POSTGRES_USER`로는 aichat에 못 붙는다. **운영이 실제 쓰는 계정**(shared-api
  DATABASE_URL)으로 붙어야 권한까지 함께 검증된다.
- ★**PostgreSQL 컨테이너는 2개다.** 하나만 보면 타입봇 DB가 죽어도 "DB 정상"이 된다.
- ★**3xx를 실패로 세지 않는다** — 타입봇 빌더는 비로그인 접근에 **307로 `/signin`**
  보내는 게 정상 동작(실측). 4xx/5xx만 장애로 센다.
- ★**pg_isready만 보면 안 된다** — 준비됐다고 답하면서 실제 질의는 실패하는 구간이
  있다(work_lessons). 실제 SELECT를 던져 응답까지 확인한다.
- **node fetch는 IPv6 폴백을 못 한다** — 이 서버는 IPv6 경로가 막혔는데
  `api.telegram.org`는 AAAA를 준다. curl은 IPv4로 폴백하지만 node fetch는 ETIMEDOUT.
  `undici` Agent `connect: { family: 4 }`로 IPv4 강제(`dns.setDefaultResultOrder`로는
  안 잡힌다).
- 텔레그램 발송 실패가 **점검 결과 기록을 막지 않는다** — 던지지 않고 false 반환.
  (예전 Brevo판은 여기서 throw해 크론이 통째로 죽었다.)

## ★감시자 자신이 차단될 수 있다 (2026-08-05)

배포 확인차 사이트를 반복 호출하다 **서버2 IP가 Vercel 봇 차단(403 Security
Checkpoint)** 에 걸렸다. 같은 시각 서버1에서는 HTTP 200 — **사이트는 정상인데 감시하는
쪽만 막힌** 상태다.

종전 코드는 403을 그대로 장애로 보고했다. 그러면 ①"사이트가 죽었다"는 거짓 경보가 나가고
②`site.ok=false`라 로그인 점검까지 통째로 스킵된다. 거짓 경보가 반복되면 진짜 장애
알림을 흘려보게 된다.

→ 403 + 본문에 `Security Checkpoint`면 **감시 IP 차단**으로 판정하고 문구에
"사이트 자체 장애가 아닐 수 있으니 다른 경로에서 확인"을 명시한다.
`ok=false`는 **유지** — 조용히 통과시키면 진짜 403 장애를 놓친다. 사람이 판단할 수 있게
'무엇이 일어났는지'를 정확히 적는 쪽을 택했다.
