## 5. 평점 숫자 차단 — 2중 방어

지시문만 믿지 않는다. 지시는 확률이고, 코드는 결정적이다.

1. **지시문**(`briefing.ts`) 6항: 평점 숫자 금지 · 가격은 확인된 범위만(없으면 null) ·
   예약 대행 언급 금지 · 확신 없으면 null · 일반론 금지 · 파크골프장이면 tips 빈 배열
2. **코드**(`sanitizeReputation()`): 숫자 평점 표현이 섞이면 **통째로 버린다**
   ```
   /(평점|별점|별|점수|스코어|rating|score)[^\d]{0,10}\d/i   ← '별점 4개' 형태
   /\d\s*(\.\d+)?\s*(점|점대|\/\s*5|\/\s*10)|★|☆|만점/
   ```
   ★첫 정규식은 **테스트가 잡아냈다** — '별점 4개'가 `별\s*\d` 를 빠져나갔다.

## 10. 2026-09-09 — '연습장'이 또 검색됐다 (사장 지적, 커밋 `da69d5e`)

목록에 **문화골프클럽**(세종 조치원)이 떴고, 화면에서 설아가 직접
"여기는 정규 코스가 아니라 실외 골프 연습장이야"라고 말하는 상태였다.

### 원인 — 카카오에 **같은 곳이 두 건**으로 등록돼 있었다

| 거리 | `category_name` | 기존 필터 |
|---|---|---|
| 471m | `스포츠,레저 > 골프` ← **말단 분류 없음** | 🔴 **통과** |
| 1200m | `스포츠,레저 > 골프 > 골프연습장` | ✅ 차단 |

`EXCLUDE_CATEGORY = /파크골프|연습장|스크린/` 는 **'연습장'이라는 글자가 있어야** 거른다.
`> 골프` 에서 끝나면 코스인지 연습장인지 **정보 자체가 없어** 제외 방식으로는 막을 수 없다.

★09-08 에 세운 "**카테고리만 신뢰한다**"는 원칙은 맞았지만,
**카테고리가 항상 말단까지 오는 건 아니라는** 전제가 빠져 있었다.

### 수정 — 제외 목록이 아니라 **허용 목록으로 뒤집는다**

```ts
const ALLOW_CATEGORY = /(^|>)\s*[^>]*골프장\s*$/;   // 말단이 '골프장'인 것만
```

카카오가 `골프장`이라고 **명시한 것만** 코스로 본다. **모르면 뺀다**
(0건이 잘못된 목록보다 낫다 — 8장의 도심 0건 원칙과 같은 태도).

### ★기존 테스트의 전제가 현실과 달랐다

`'해솔리아CC', '스포츠,레저 > 골프' → true` 를 기대하고 있었는데, 카카오 실측 결과
**본체는 `> 골프장`** 이고 `> 골프` 로 오는 건 **클럽하우스(부속시설)** 였다.
테스트를 실제 데이터에 맞게 정정했다.
