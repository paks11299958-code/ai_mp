HOW IT WORKS

사람이 기다리는 구간을
세 단계로 줄였습니다

지시 → 개발 → 검증 → 배포. 중간에 사람이 붙잡고 있어야 하는 단계가 없습니다.

1

지시를 보냅니다

텔레그램에 필요한 걸 그대로 적으면 됩니다. 헤르메스가 요구사항을 정리해 개발 pane으로 넘깁니다.

2

에이전트가 만듭니다

Developer가 코드를 작성하면 Reviewer가 별도 세션에서 검증합니다. 통과할 때까지 왕복합니다.

3

배포하고 알립니다

검증을 통과한 결과만 배포하고, 완성된 사이트 주소를 텔레그램으로 회신합니다.

FEATURES

믿고 맡기려면
이 네 가지가 필요했습니다

메이커–체커 검증

만든 에이전트와 검증하는 에이전트를 분리했습니다. 자기 코드를 자기가 통과시키지 않습니다.

자동 배포

검증 통과 즉시 배포까지 이어집니다. 로컬 빌드 결과가 아니라 실제 운영 URL로 확인합니다.

pane 자동 회수

작업이 끝나면 세션을 정리합니다. 남은 pane이 비용으로 새어나가지 않습니다.

전 구간 알림

접수·개발·검증·배포 각 단계를 텔레그램으로 알립니다. 어디서 멈췄는지 바로 보입니다.

DEPLOY

배포됐다는 말 대신,
열리는 주소를 드립니다

빌드 통과는 검증이 아닙니다. 운영에 실제로 반영됐는지까지 확인한 뒤에 완료로 처리합니다.

  • 운영 배포 상태를 API로 직접 조회
  • 이번 변경의 고유 문자열을 산출물에서 확인
  • 실제 URL 렌더까지 확인 후 회신
