# PRD — AI 학습코칭 (AI 데이터 통합 MVP)

**버전** 1.1
**대상 프로젝트** aichat.dbzone.kr (AI 데이터) — 기존 프로젝트에 기능 추가
**문서 목적** Claude Code가 MVP를 자율 개발하기 위한 단일 기준 문서. 여기 없는 기능은 구현하지 않는다.

---

## 0. 착수 전 확인 사항

이 문서는 기존 코드베이스를 직접 확인하지 않은 상태에서 작성되었다. 개발 착수 전 아래를 먼저 조사하고, 사실과 다르면 **사용자에게 보고한 뒤** 진행한다.

1. 프레임워크와 버전 (Next.js App Router / Pages Router / 그 외)
2. 인증 기능 존재 여부와 방식 — **있으면 반드시 재사용한다. 새 인증을 만들지 않는다.**
3. 페르소나 목록의 저장 위치 (DB 테이블 / 코드 하드코딩 / JSON)
4. 기존 Postgres 접속 방식과 ORM/쿼리 빌더 사용 여부
5. 기존 테이블 명명 규칙
6. 기존 디자인 시스템 (Tailwind 여부, 색상 토큰, 공용 컴포넌트)

**신규 UI는 기존 사이트의 디자인 톤(다크 계열, `#030712` 기반)을 따른다. 별도 디자인 언어를 도입하지 않는다.**

## 1. 제품 정의

### 1.1 한 줄 정의

사용자가 입력한 학습 목표를 AI가 커리큘럼으로 쪼개고, 매일 분량을 배정하고, 오답을 기억했다가 다시 물어보는 **지속형 학습 코치**. AI 데이터의 페르소나 중 하나로 진입하며, 다른 페르소나와 달리 각각의 서비스로 연결된다.

### 1.2 해결하는 문제

범용 AI 챗봇으로도 공부할 수 있다. 하지만 챗봇은 이전에 무엇을 틀렸는지 기억하지 않고, 오늘 무엇을 할지 정해주지 않으며, 사용자가 질문하지 않으면 아무 일도 일어나지 않는다.

이 제품의 차별점은 **주입식 지식이 아니라 학습 진도 구조**에 있다.

### 1.3 타깃

학습 주제를 스스로 정할 수 있는 성인 및 계획된 학습자. 주제는 한정하지 않는다.

### 1.4 비목표

강의 영상, 콘텐츠 마켓플레이스, 커뮤니티, 실시간 대화형 챗봇(제한적으로만 제공, 6.4 참조).

## 2. 진입 구조

```
aichat.dbzone.kr (메인)
        │
        ├── 페르소나 카드들 (기존)
        │
        └── [AI 학습코칭] 카드  ← 신규
                 │
                 │
          /learning  (서비스 소개 랜딩)
                 │
          "학습 서비스 신청" 버튼
                 │
                 │
          /learning/onboarding  (목표 입력)
                 │
                 │
             로그인 요구 ↓
                 │
                 │
          커리큘럼 생성 → 확정 → 대시보드
```

### 2.1 페르소나 카드

- 기존 페르소나 목록에 카드 1개 추가
- 다른 카드가 채팅으로 이동하는 것과 달리 `/learning`으로 이동
- 카드에 "학습 코칭" 같은 구분 배지를 넣어 성격이 다름을 표시

### 2.2 로그인 타이밍 (★ 중요)

**목표를 입력하기 전에 로그인을 요구하지 않는다.** 목표 입력과 구조화 질문 4개를 먼저 받고, 커리큘럼 생성 직전에 로그인을 요구한다.

이유: 아무것도 입력하지 않은 상태에서 가입 벽을 세우면 이탈률이 크게 오른다. 이미 목표를 적은 사용자는 결과를 보기 위해 로그인한다.

구현: 입력값을 `sessionStorage`에 임시 보관 → 로그인 완료 후 복원하여 커리큘럼 생성 진행. 로그인 이후 입력은 같이 남아 있어야 한다.

## 3. 핵심 루프

```
목표 설정 → AI 커리큘럼 생성 → 매일 학습 배정
   → 퀴즈 응시/채점 → 오답은 복습 후 재삭제
   → 간격 반복으로 재출제 → 주간 리포트 → 커리큘럼 조정 → (반복)
```

이 루프가 제품의 본체다. 이게 돌면 제품이 산다.

## 4. 사용자 흐름

### 4.1 온보딩 (3분 이내)

1. `/learning`에서 "학습 서비스 신청" 클릭
2. 학습 목표 자유 입력 — 예: "3개월 안에 정보처리기사 필기 합격"
3. 구조화 질문 4개
   - 목표 기간 (4 / 8 / 12주 / 직접 입력)
   - 주당 학습 일수 (3 / 5 / 7일)
   - 1회 학습 시간 (15 / 30 / 60분)
   - 현재 수준 (입문 / 기초 있음 / 중급)
4. **로그인** (기존 인증 재사용)
5. AI 커리큘럼 생성 (로딩 화면, 최대 30초)
6. 커리큘럼 확인 → 수정 요청 1회 가능 → 확정
7. 알림 시간 설정 → 대시보드

### 4.2 일일 흐름

알림 수신 → 대시보드 → 오늘의 학습 읽기(3~10분) → 퀴즈 3~5문항 → 즉시 채점·해설 → 오답 처리 및 연속일 갱신

### 4.3 주간 흐름

매주 일요일 리포트 생성 → 진도율·정답률·취약 영역·조정 제안 → 사용자가 수락 또는 거절

## 6. AI 동작 명세

### 6.1 커리큘럼 생성

- 입력: 목표 텍스트, 기간, 주당 일수, 1회 시간, 수준
- 출력: JSON → 주차 배열, 각 주차의 모듈 배열(모듈 = 하루치 학습 단위)
- 제약: 총 모듈 수 = 기간(주) × 주당 일수. 모듈 제목 20자 이내, 학습 목표 1문장 포함
- 호출 시점: 온보딩 1회 + 수정 요청 시 최대 1회
- 모델: 상위 모델 (품질 우선)

### 6.2 학습 콘텐츠 생성

- 입력: 모듈 제목, 학습 목표, 수준, 1회 학습 시간
- 출력: 마크다운 본문 (15분 → 약 600자 / 30분 → 약 1200자 / 60분 → 약 2000자)
- 구성: 핵심 개념 → 예시 → 한 줄 요약
- 호출 시점: 해당 모듈 최초 열람 시 1회. **생성 후 DB에 저장하고 재생성하지 않는다.**
- 모델: 중간 모델

### 6.3 문항 생성 및 채점

- 출력: JSON → 4지선다 3~5문항. 각 문항에 정답, 해설, 난이도(1~3), 태그(개념명)
- **채점은 서버에서 문자열 비교로 수행한다. AI 호출 없음.**
- 호출 시점: 6.2와 **동일 호출에 통합**하여 1회로 처리
- 모델: 중간 모델

### 6.4 질문하기 (제한적 대화)

- 학습 화면 안에서만 노출, 현재 모듈 본문을 컨텍스트로 주입
- **하루 10회 제한**, 초과 시 429
- 히스토리는 해당 모듈 내 최대 6회
- 모델: 소형~중간 모델

### 6.5 주간 리포트

- 입력: 지난 주 완료 모듈, 정답률, 태그별 오답 분포
- 출력: 요약 3문장 + 취약 태그 3개 + 다음 주 조정 제안
- 호출: 주 1회, 중간 모델

### 6.6 공통 규칙

- 구조화 출력은 zod 스키마로 검증하고 파싱 실패 시 최대 2회 재시도
- 실패 시 재시도 버튼을 노출하고 학습 진도를 잃지 않는다
- 모든 호출은 `lc_ai_usage_log`에 토큰 수와 비용을 기록한다

## 7. 간격 반복 알고리즘

SM-2 단순화 버전. **외부 라이브러리 금지, 직접 구현.**

```
오답 발생 → 항목 생성, interval = 1일, ease = 2.5
복습 정답 → interval = round(interval × ease), ease += 0.1 (최대 3.0)
복습 오답 → interval = 1, ease -= 0.2 (최소 1.3)
interval > 60일 → mastered 처리, 대상에서 제거
```

- 하루 최대 5개까지만 복습 배정
- 복습은 오늘의 학습보다 먼저 노출

## 8. 데이터 모델

기존 Postgres에 테이블을 추가한다. **모든 신규 테이블은 `lc_` 접두사를 붙여 기존 테이블과 충돌하지 않게 한다.** 기존 테이블은 수정하지 않는다.

사용자 식별자는 **기존 사용자 테이블의 PK**를 FK로 참조한다. 새 users 테이블을 만들지 않는다. (0장에서 실제 테이블명 확인 후 반영)

```
lc_profiles
  user_id(FK, PK), level, notify_hour, study_days(int[]),
  streak, last_completed_date, timezone

lc_goals
  id, user_id(FK), title, raw_input, duration_weeks, days_per_week,
  minutes_per_session, status(active|paused|done), created_at

lc_modules
  id, goal_id(FK), week_no, order_no, title, objective,
  content_md(nullable), content_generated_at, status(pending|open|done)

lc_daily_tasks
  id, user_id(FK), module_id(FK), assigned_date, completed_at, score

lc_questions
  id, module_id(FK), stem, choices(jsonb), answer, explanation,
  difficulty(1-3), tag

lc_attempts
  id, user_id(FK), question_id(FK), selected, is_correct,
  is_review(bool), created_at

lc_review_items
  id, user_id(FK), question_id(FK), interval_days, ease,
  due_date, state(active|mastered)

lc_weekly_reports
  id, user_id(FK), week_start, metrics(jsonb), summary_md,
  suggestion(jsonb), accepted(bool)

lc_subscriptions
  id, user_id(FK), plan(free|pro), status, current_period_end, provider_ref

lc_ai_usage_log
  id, user_id(FK), purpose, model, input_tokens, output_tokens,
  cost_usd, created_at
```

인덱스: `lc_daily_tasks(user_id, assigned_date)`, `lc_review_items(user_id, due_date, state)`, `lc_attempts(user_id, created_at)`

### 8.1 접근 제어

Supabase RLS를 쓰지 않으므로 **애플리케이션 레이어에서 소유권을 검증한다.**

- 모든 조회/변경 쿼리에 `user_id = :sessionUserId` 조건을 포함한다
- `lib/learning/auth.ts`의 `assertOwnership(resource, userId)` 공용 헬퍼를 만들고 모든 API 핸들러에서 호출한다
- 세션 사용자 ID를 클라이언트 입력에서 받지 않는다. 항상 서버 세션에서 읽는다

## 9. API 명세

| Method | 경로 | 설명 |

## 10. 기술 스택

- **프레임워크**: 기존 프로젝트 스택을 따른다 (0장에서 확인)
- **DB**: 기존 Postgres에 직접 연결
- **ORM/마이그레이션**: 기존 프로젝트에 이미 있으면 그것을 쓴다. 없으면 **Drizzle ORM + drizzle-kit**으로 통일한다. 마이그레이션 파일은 반드시 버전 관리한다
- **인증**: 기존 인증 재사용. 없는 경우에만 Auth.js(NextAuth) + Postgres 어댑터
- **스타일**: 기존 디자인 시스템 재사용
- **AI**: Anthropic API
- **결제**: MVP 미연동. `lc_subscriptions` 테이블과 플랜 분기 로직만 구현, 결제 UI는 "준비 중"
- **알림**: 웹 푸시(Web Push API) + 이메일 폴백
- **스케줄러**: 기존 배포 환경의 스케줄러 사용. 없으면 시크릿 헤더로 보호된 HTTP 엔드포인트 + 외부 cron

> **iOS 제약**: iOS Safari는 홈 화면에 추가한 PWA에서만 웹 푸시를 지원한다. 온보딩 마지막 단계에서 "홈 화면에 추가" 안내를 노출하고, 미설치 사용자는 이메일로 폴백한다.

## 11. 비용 통제 정책

선택 사항이 아니다. 아래를 누락한 구현은 완료로 인정하지 않는다.

1. 학습 본문과 문항을 **모듈당 1회만 생성**하고 DB에 영구 저장한다
2. 채점에 AI를 사용하지 않는다
3. 질문하기는 하루 10회로 제한하고 우회 경로를 만들지 않는다
4. 대화 히스토리는 해당 모듈 내 최대 6회까지만 컨텍스트에 포함한다
5. 모든 호출을 `lc_ai_usage_log`에 기록하고, SQL로 사용자별 사용량을 조회할 수 있어야 한다
6. **사용자 1인당 월 AI 사용량 2,000원 이하**로 설계한다

페르소나 카드 추가, 서비스 랜딩, 온보딩(로그인 지연 방식), 커리큘럼 생성/확정, 일일 배정, 학습 본문, 퀴즈, 서버 채점, 오답 노트, 간격 반복, 주간 리포트, 웹 푸시 + 이메일, 반응형, 설정, 사용량 로깅

**제외 (구현 금지)**
결제 연동, 음성 기능, 랭킹, 관리자 대시보드, 다국어, 파일 업로드, 음성, 이미지 생성, 추천 알고리즘, A/B 테스트, 기존 페르소나 기능 변경

## 13. MVP 완료 조건

전부 통과해야 완료다.

- [ ] 메인에서 학습코칭 카드가 노출되고 `/learning`으로 이동한다
- [ ] 로그인하지 않은 상태에서 목표 입력과 질문 4개를 끝까지 진행할 수 있다
- [ ] 로그인 후 입력값이 손실 없이 복원되어 커리큘럼 생성으로 이어진다
- [ ] 신청 클릭부터 커리큘럼 확정까지 3분 이내 도달한다
- [ ] 확정 즉시 `lc_daily_tasks`가 기간 전체에 대해 생성된다
- [ ] 학습 본문이 최초 1회만 생성되고 재접속 시 DB에서 로드된다
- [ ] 퀴즈 제출 시 AI 호출 없이 채점되고 해설이 표시된다
- [ ] 오답이 `lc_review_items`에 저장되고 다음 날 복습 항목이 노출된다
- [ ] 간격 반복 계산이 7장 공식과 일치한다 (단위 테스트 포함)
- [ ] 타 사용자 리소스 접근 시 403이 반환된다 (통합 테스트 포함)
- [ ] Cron 실행 시 알림 시간대에 맞춰 푸시 또는 이메일이 발송된다
- [ ] 주간 리포트가 생성되고 조정안 수락 시 커리큘럼에 반영된다
- [ ] 360px 폭에서 모든 신규 화면이 가로 스크롤 없이 표시된다
- [ ] 기존 페르소나 기능이 전부 그대로 동작한다 (회귀 확인)
- [ ] 모든 AI 호출이 `lc_ai_usage_log`에 기록된다
- [ ] 빌드 및 테스트가 무오류로 통과한다
- [ ] 시드 데이터로 온보딩~주간 리포트 E2E 시나리오를 1회 왕복한다
