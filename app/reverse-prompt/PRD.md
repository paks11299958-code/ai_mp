# PRD — 리버스 프롬프트 (aichat 기능 추가)

**버전** 1.0
**대상 프로젝트** 기존 프로젝트(aichat.dbzone.kr)에 기능 추가
**문서 목적** 자율 개발 에이전트가 MVP를 구현하기 위한 단일 기준 문서. 여기 없는 기능은 구현하지 않는다.

---

## 0. 착수 전 확인 사항

이 문서는 기존 코드베이스를 확인하지 않은 상태에서 작성되었다. 개발 시작 전 아래를 조사하고, 사실과 다르면 **사용자에게 보고한 뒤** 진행한다.

### 이미 확인된 것 (조사 불필요)

| 항목 | 내용 |
|---|---|
| 프론트엔드 | Vite + React SPA, Vercel 배포 |
| 백엔드 | shared-api (Express + Prisma) |
| DB | PostgreSQL (서버1) |
| 서버1 | 운영 — shared-api, Postgres |
| 서버2 | 개발 |
| 서버3 | GPU — ComfyUI (**MVP에서 사용하지 않음**) |

### 조사할 것

1. Express/Prisma/React/Node 버전
2. 인증 방식과 세션에서 사용자 ID를 얻는 코드 위치 — **있으면 반드시 재사용한다**
3. 사용자 테이블명과 PK 컬럼명, 타입 (uuid / int / cuid)
4. Prisma 스키마 파일 경로. **여러 벌이면 어느 것이 정본인지 확인한다**
5. 기존 테이블·모델 명명 규칙 (snake_case / PascalCase, `@@map` 사용 여부)
6. 디자인 시스템 — 색상 토큰, 공용 컴포넌트 위치, 라우팅 패턴
7. 파일 업로드 처리 방식이 이미 있는지 (multer 등), 용량 상한 설정
8. 기존 AI 호출 코드가 있다면 그 방식 (SDK, 모델, 키 관리)
9. 배포 방식 (Vercel 자동배포 트리거, shared-api 재시작 방법)
10. Rate limit / IP 기반 제한 미들웨어가 이미 있는지

**신규 UI는 기존 디자인 톤을 따른다. 별도 디자인 언어를 도입하지 않는다.**

## 1. 제품 정의

### 1.1 한 줄 정의

**이미지 생성을 하는 사람이** 마음에 드는 이미지 한 장을 올리면 **Midjourney와 Stable Diffusion 양쪽에서 바로 쓸 수 있는 프롬프트를** 얻고 **모아둘 수 있게 하는** 도구.

### 1.2 해결하는 문제

이미지 생성 사용자는 "이런 느낌"을 이미 눈으로는 알고 있는데 그걸 프롬프트 문장으로 옮기지 못한다. 특히 MJ와 SD는 문법이 다르다 — MJ는 자연어 나열에 `--ar`, `--style` 같은 파라미터를 붙이고, SD는 태그 나열에 negative prompt와 가중치를 쓴다. 한쪽에서 쓰던 프롬프트를 다른 쪽에 그대로 넣으면 결과가 무너진다.

범용 AI 챗봇도 이미지를 읽고 프롬프트를 만들어줄 수는 있다. 챗봇이 구조적으로 못 하는 것은 다음이다.

- **두 형식을 일관된 규칙으로 동시에** 뽑아주지 않는다. 매번 형식이 달라진다
- **모아두지 않는다.** 대화가 흘러가면 지난 프롬프트를 다시 찾을 수 없다
- 결과를 바로 복사해 쓸 수 있는 형태로 주지 않는다

이 제품의 본체는 "이미지를 읽는 것"이 아니라 **일관된 형식 + 보관**이다.

### 1.3 타깃

불특정 다수. 로그인 없이 접근 가능한 공개 도구로 운영한다.
실사용 중심은 MJ/SD를 이미 쓰거나 쓰려는 사용자지만, 진입 조건을 걸지 않는다.

### 1.4 제품의 목적

**이 기능 자체로 수익을 내지 않는다.** aichat.dbzone.kr의 회원가입 유입 경로다.
따라서 성공은 매출이 아니라 **비로그인 사용자의 회원 전환율**로 측정한다.
그리고 원가는 수익이 상계되지 않는 순수 지출이므로, 상한 통제가 이 문서에서 가장 중요한 부분이다.

### 1.5 비목표 (Non-goals)

아래는 **구현하지 않는다.**

- **프롬프트로 이미지를 재생성해 미리보기를 보여주는 기능** — V2 후보. MVP에서 서버3(ComfyUI)을 호출하지 않는다
- 이미지 편집, 업스케일, 배경 제거 등 이미지 가공
- 여러 장 일괄 업로드 / 배치 처리
- 프롬프트 자동 번역 (한국어 출력)
- 프롬프트 공유, 공개 갤러리, 좋아요, 댓글
- 결제 / 유료 플랜
- DALL·E, Flux 등 MJ·SD 외 형식 추가
- 사용자가 올린 원본 이미지의 서버 보관

## 2. 진입 구조

```
[aichat.dbzone.kr 메인]
      │
      └─ [리버스 프롬프트]  ← 신규 진입점
             │
             ↓
      [S1 업로드 화면]  (로그인 불필요)
             │
      이미지 업로드 → 프롬프트 결과 표시
             │
      ┌──────┴──────┐
      │             │
  1~2회차        3회차 시도
  그대로 사용     [로그인 요구] ★
                    │
                    ↓
              [S2 보관함] + 무제한에 가까운 사용
```

### 2.1 로그인 타이밍

로그인은 **비로그인 일일 체험 2회를 모두 쓴 뒤 3회차를 시도하는 시점**에 요구한다.

- 첫 화면에는 로그인 유도 요소를 두지 않는다. 업로드 영역만 보인다
- 2회차 결과 화면 하단에 "저장하려면 로그인" 안내를 **부드럽게** 노출한다 (차단하지 않는다)
- 3회차 업로드를 시도하면 로그인 모달을 띄운다
- 로그인 이탈 시 **업로드하려던 이미지를 잃지 않는다.** 파일을 `sessionStorage`에 base64로 임시 보관했다가 로그인 복귀 후 자동으로 분석을 이어서 실행한다
- 임시 보관 용량 상한은 5MB. 초과 시 "로그인 후 다시 올려주세요"로 안내한다

**보관함은 로그인 사용자 전용이다.** 비로그인 결과는 브라우저를 닫으면 사라진다. 이것이 로그인의 주된 이유다.

## 3. 핵심 루프

```
[진입] → [이미지 업로드] → [VLM 분석 1회] → [MJ/SD 프롬프트 표시]
                                                    │
                                            [보관함에 저장]
                                                    │
                                        [보관함에서 꺼내 재사용·변형]
                                                    │
                                                 (반복)
```

이 루프가 제품의 본체다. **[보관함에 저장] 단계가 빠지면 일회용 도구가 되고 재방문 이유가 없어진다.**

## 4. 사용자 흐름

### 4.1 최초 (온보딩) — 목표 30초 이내

1. 리버스 프롬프트 페이지 진입. 설명 문구 한 줄과 업로드 영역만 보인다
2. 이미지를 끌어다 놓거나 클릭해 선택한다
3. 로딩 표시와 함께 분석이 진행된다 (목표 10초 이내)
4. MJ 프롬프트와 SD 프롬프트가 탭 또는 상하 2단으로 표시된다. 각각 복사 버튼이 있다
5. 하단에 "오늘 1회 남음" 표시와 함께 로그인 시 보관함을 쓸 수 있다는 안내가 나온다

### 4.2 반복 사용 (로그인 사용자)

1. 페이지 진입 시 최근 보관 항목 3개가 업로드 영역 아래에 표시된다
2. 새 이미지를 올려 분석하면 자동으로 보관함에 저장된다
3. 보관함에서 지난 프롬프트를 복사하거나 삭제한다

### 4.3 주기적

없음. 스케줄러를 사용하지 않는다.

|---|---|---|---|
| S1 | 업로드 + 결과 | `/reverse-prompt` | 드래그앤드롭 영역, 로딩 상태, MJ/SD 결과 2단, 복사 버튼, 잔여 횟수, 최근 항목 3개(로그인 시) |

- 복사 버튼은 클릭 시 "복사됨" 피드백을 준다

## 6. AI 동작 명세

### 6.1 이미지 → 프롬프트 분석

- **입력**: 사용자 업로드 이미지 1장 (서버에서 리사이즈 후 전달)
- **출력**: 아래 스키마의 JSON **단일 응답**

```json
{
  "subject": "핵심 피사체 묘사",
  "style": "화풍/매체",
  "composition": "구도·앵글",
  "lighting": "조명",
  "color": "색감·팔레트",
  "mood": "분위기",
  "details": ["세부 요소", "..."],
  "aspectRatio": "16:9",
  "midjourney": "MJ 형식 완성 프롬프트 (--ar 등 파라미터 포함)",
  "stableDiffusion": {
    "positive": "태그 나열 형식",
    "negative": "negative prompt"
  }
}
```

- **제약**
  - **호출은 이미지 1장당 정확히 1회.** MJ용과 SD용을 나눠 두 번 호출하지 않는다. 한 번의 응답에서 두 형식을 모두 받는다. 이것이 원가를 절반으로 만든다
  - 출력은 영어로 생성한다 (MJ/SD 모두 영어 프롬프트가 표준)
  - JSON 스키마 검증에 실패하면 최대 2회 재시도하고, 그래도 실패하면 사용자에게 재시도 UI를 노출한다
  - 실존 인물로 식별 가능한 얼굴은 개인 식별 표현 대신 일반적 묘사로 기술하게 한다
- **호출 시점**: 사용자가 이미지를 업로드한 **그 순간 1회.** 결과 조회·보관함 열람·재접속 시에는 호출하지 않는다
- **캐시**: 이미지 SHA-256 해시가 일치하면 기존 분석 결과를 재사용하고 **AI를 호출하지 않는다**
- **모델**: ★**`gemini-3.5-flash-lite`로 확정**(2026-08-14 사용자 결정). 모델명은
  `lib/reverse-prompt/constants.ts` 상수 1곳에서만 정의하고 호출부에 인라인하지 않는다
  (학습코칭에서 호출부 5곳이 각자 하드코딩해 원가가 옛 단가로 기록된 사고가 있었다).

  **선정 근거 — 공식 지원 중단 표 한 줄이 결정적이다**

  아래는 전부 Gemini API 공식 문서(`ai.google.dev`)에서 직접 확인한 값이다(2026-08-14).
  집계 사이트·블로그 값을 인용하지 않는다.

  | 모델 | 릴리스 | 종료일 | 권장 대체 |
  |---|---|---|---|
  | ★`gemini-3.5-flash-lite` | 2026-07-21 (GA) | **없음** | — |
  | `gemini-3.1-flash-lite` | 2026-05-07 | **2027-05-07** | **`gemini-3.5-flash-lite`** |
  | `gemini-2.5-flash` / `2.5-flash-lite` / `2.5-pro` | 2025-06~07 | **미발표** | — |

  - ★**Vertex 경로에서 실제로 호출 가능해야 한다** — 이것이 선정 기준에 추가됐다(2026-08-14).
    shared-api는 Gemini API가 아니라 **Vertex AI**로 부르는데, **두 경로의 모델 가용성이 다르다.**
    Gemini API에 존재하는 모델이 Vertex에는 없을 수 있고, Vertex 안에서도 **리전별로 다르다.**
    전 리전 실측 결과:

    | 모델 | `global` | us-central1 / us-east5 / europe-west4 / asia-northeast3·1 |
    |---|---|---|
    | `gemini-3.5-flash-lite` | ✅ | **전부 404** |
    | `gemini-3.1-flash-lite` | ✅ | 전부 404 |
    | `gemini-2.5-flash` | ✅ | ✅ (구세대라 리전 배포 완료) |

    → **`location: 'global'` 고정이 필수다**(`RP_VERTEX_LOCATION`). 기존 `getGeminiClient()`는
    `us-central1` 하드코딩이라 이 모델에서 404가 났고(실측), `lib/gemini.ts`는 기존 파일이라
    수정하지 않고 이 기능만 별도 Vertex 클라이언트를 쓴다.
  - **구글이 지원 중단 표에서 `gemini-3.1-flash-lite`의 대체 모델로 `gemini-3.5-flash-lite`를
    직접 지정했다.** 3.1을 고르는 것은 구글이 "여기로 옮기라"고 적어둔 길을 역주행하는 것이며,
    **예고된 재마이그레이션**을 사서 하는 셈이다.
  - 3.5-flash-lite는 **2026-07-21 GA**이고 **종료일이 없다.** 최신 stable이며 수명이 가장 길다.
  - `gemini-2.5-flash`는 종료일이 미공표지만 **이전 세대**다. 신규 기능을 구세대로 시작할
    이유가 없고, 아래 404 사고 이력도 이 계열에서 나왔다.
  - 사이트 전역이 이미 Gemini 주류(23곳)라 키·정책·에러 처리가 일치한다.

  **단가 비교** — 공식 가격표에서 직접 확인.

  | 모델 | 입력 $/1M | 출력 $/1M | 1건 원가 | 월 1만 건 |
  |---|---|---|---|---|
  | ★`gemini-3.5-flash-lite` | $0.30 | $2.50 | $0.00220 | $22.0 |
  | `gemini-3.1-flash-lite` | $0.25 | $1.50 | $0.00142 | $14.2 |

  3.1이 35% 싸지만 **2027-05-07 종료가 확정**돼 있어 채택하면 1년 안에 같은 마이그레이션을
  다시 해야 한다. 월 $7.8 차이는 재작업 비용보다 작다. **3.5-flash-lite로 간다.**

  ★**2.5 계열 은퇴에 대한 기록**: 초안 검토 중 "2.5-flash가 2026-10-16 종료"라는 값이
  제시됐으나, **공식 지원 중단 표를 직접 열어 확인한 결과 2.5-flash/2.5-flash-lite/2.5-pro는
  셋 다 "No shutdown date announced"**였다. 10-16은 집계 사이트·블로그가 퍼뜨린 2차 출처
  값이며 공식 표에 없다(구글이 뺐거나 연기한 것으로 보인다). **문서에 넣지 않는다.**
  다만 2026-07-09에 `gemini-2.5-flash`가 `404 NOT_FOUND: "no longer available"`로
  끊겨 프로덕션이 중단된 사고는 실재한다(구글 답변: *"config 이슈였고 롤백했다"*).
  종료일 표기와 무관하게 모델은 예고 없이 끊길 수 있으므로 **모델명은 상수 1곳에 두어
  교체가 한 줄로 끝나게 한다**([포럼 스레드](https://discuss.ai.google.dev/t/gemini-2-5-flash-deprecated-without-warning-earlier-than-shutdown-date/174217)).

  ★**입력 토큰은 이미지 크기와 무관하다**(2026-08-14 실측). `countTokens` 결과:
  256px·384px·1024×576·1024×1024·2048px·3000×2000이 **전부 ~1,090토큰**으로 동일했다.
  따라서 11장 4항의 "1024px 리사이즈가 원가를 좌우한다"는 이 모델에는 **해당하지 않는다.**
  리사이즈는 여전히 하되 근거가 바뀐다 → **페이로드 축소(413 회피)·전송 지연·EXIF 제거**.

  ★**실측 원가 — 8개 소재로 확정(2026-08-15, 묶음 E-1).** 상세 표는 11장 참조.
  평균 **$0.001240/건**(입력 1,641 · 출력 299), 범위 $0.001071~$0.001364.
  입력은 사실상 고정(±1.5%)이고 변동은 출력에서만 온다.

  | 항목 | 값 |
  |---|---|
  | 입력 토큰 | **1,664** (이미지 + 시스템/사용자 프롬프트) |
  | 출력 토큰 | **306** (6.1 스키마 전체) |
  | **1건 원가** | **$0.001264** |
  | 응답 시간 | 약 4.0초 (캐시 적중 시 0.1초) |

  월 1만 건 기준 약 **$12.6**. 앞서 산식으로 추정한 $0.0022보다 **43% 저렴**하다
  (출력이 예상 700토큰의 절반 이하였다). 캐시 적중분은 원가가 0이므로 실제로는 더 낮아진다.
- **호출 방식**: HTTP API. **구독제 CLI를 엔진으로 쓰지 않는다**

### 6.2 공통 규칙

- 구조화 출력은 스키마로 검증하고 파싱 실패 시 최대 2회 재시도
- 실패 시 재시도 UI를 노출하고 사용자의 업로드 상태를 잃지 않는다
- 모든 호출을 사용량 로그 테이블에 토큰 수와 원가와 함께 기록한다. **예외 없다**

## 7. 이미지 전처리

원가와 개인정보 양쪽에 직결되므로 명세로 고정한다.

```
업로드 수신
  → 형식 검증 (jpeg/png/webp만 허용, 그 외 거부)
  → 용량 검증 (★5MB 초과 거부 — 2026-08-14 정정, 초판 10MB)
  → SHA-256 해시 계산          ← 캐시 키
  → 긴 변 1024px로 리사이즈     ← VLM 입력 토큰 원가를 좌우
  → JPEG 품질 85로 재인코딩
  → EXIF 전량 제거              ← GPS 등 위치정보 제거
  → VLM에 전달
  → 128px 썸네일 생성 (로그인 사용자만)
  → 원본과 리사이즈본 메모리에서 폐기. 디스크에 쓰지 않는다
```

**원본 이미지는 어떤 경우에도 서버에 저장하지 않는다.**

### ★용량 상한 5MB — 근거 (2026-08-14 정정)

초판의 10MB는 **실제로 도달할 수 없는 값**이라 5MB로 낮춘다.

1. **Vercel 프록시가 10MB에서 순수 413을 던진다.** 플랫폼 레벨 제약이며 실측으로 확인됐다
   (11MB부터 413, `FUNCTION_PAYLOAD_TOO_LARGE`가 아닌 순수 413 — `shared-api/app.ts` 주석).
   Express의 `express.json({limit})`를 아무리 올려도 그 앞단에서 막힌다.
2. **base64는 +33% 팽창한다.** 원본 10MB는 전송 시 약 13.3MB가 되어 위 상한을 넘는다.
   즉 초판 값으로는 상한에 도달하기 전에 원인 불명의 413을 보게 된다.
3. **PRD 2.1의 `sessionStorage` 임시 보관 상한이 5MB다.** 업로드 상한을 여기 맞추면
   "올릴 수는 있는데 로그인 복귀 시 복원은 안 되는" 구간이 사라진다.

검사는 미들웨어가 아니라 **핸들러 진입 직후 base64 문자열 길이**로 한다
(`app.ts`의 전역 파서는 수정 금지 대상이라 라우트별 파서를 덧대도 이미 파싱된 뒤다).
프론트에서도 파일 선택 즉시 같은 상한으로 거른다.

**썸네일 정책 (사용자 확인 필요 — 묶음 A에서 확정)**
보관함에서 항목을 식별하려면 최소한의 시각 단서가 필요하다. 원본을 저장하지 않으므로 128px 썸네일을 DB에 base64로 보관하는 것을 기본안으로 한다. 이것도 원하지 않으면 보관함은 프롬프트 텍스트와 생성일만으로 구성한다.

## 8. 데이터 모델

> ★**2026-08-14 묶음 A에서 확정 완료.** 아래 초안 대비 실제 반영된 정정 3가지:
>
> | 초안 | 확정 | 근거 |
> |---|---|---|
> | `analysis **Json**` | `analysisJson **String**` | 이 스키마는 **Json 타입 사용처가 0곳**이다(71개 모델 전수 확인). 전부 `String`에 `JSON.stringify` 저장하는 관례(`choicesJson`·`favoritesJson`·`analysisJson` 선례) |
> | `costUsd **Decimal**` | `costUsd **Float**` | `LcAiUsageLog.costUsd`가 Float. Decimal 사용처 0곳 |
> | `userId FK → 사용자 PK` | `userId **Int**` | `User.id`가 `Int @default(autoincrement())`. uuid/cuid 아님 |
>
> 명명은 **PascalCase 모델 + camelCase 컬럼 + `@@map` 미사용**(71개 중 68개 관례).
> 실제 스키마: `shared-api/prisma/schema.prisma`, DDL: `shared-api/prisma/reverse-prompt-ddl.sql`.

```
RpItem                          보관 항목 (로그인 사용자 전용)
  id            PK
  userId        FK → 기존 사용자 테이블 PK
  imageHash     String    (SHA-256)
  thumbnail     String?   (base64, 128px) — 썸네일 정책 확정 후
  analysis      Json      (6.1 스키마 전문)
  mjPrompt      Text
  sdPositive    Text
  sdNegative    Text
  createdAt     DateTime

RpAnalysisCache                 이미지 해시 기반 분석 캐시
  imageHash     PK (SHA-256)
  analysis      Json
  hitCount      Int
  createdAt     DateTime
  lastUsedAt    DateTime

RpGuestUsage                    비로그인 일일 사용량
  id            PK
  visitorKey    String    (IP 해시 + 브라우저 지문 조합, 원본 IP를 저장하지 않는다)
  usedDate      Date
  count         Int
  UNIQUE(visitorKey, usedDate)

RpAiUsageLog                    AI 호출 로그 (예외 없이 전건 기록)
  id            PK
  userId        FK? (비로그인이면 null)
  visitorKey    String?
  purpose       String    ('reverse_prompt')
  model         String
  inputTokens   Int
  outputTokens  Int
  costUsd       Decimal   → 확정: Float
  cacheHit      Boolean
  environment   String    ★추가(2026-08-14) production | development
  createdAt     DateTime
```

**인덱스**
- `RpItem(userId, createdAt DESC)` — 보관함 목록
- `RpItem(imageHash)`
- `RpAnalysisCache(lastUsedAt)` — 오래된 캐시 정리용
- `RpGuestUsage(visitorKey, usedDate)` UNIQUE
- `RpAiUsageLog(userId, createdAt)`, `RpAiUsageLog(createdAt)` — 원가 집계

**원가 조회가 가능해야 한다.** 아래 형태의 쿼리가 동작해야 한다.

```sql
SELECT "userId", COUNT(*) AS calls, SUM("costUsd") AS cost
FROM "RpAiUsageLog"
WHERE "createdAt" >= date_trunc('month', now())
  AND "cacheHit" = false
  AND "environment" = 'production'   -- ★개발 검증 호출 제외
GROUP BY "userId" ORDER BY cost DESC;
```

### ★`environment` 컬럼 (2026-08-14 추가)

`RpAiUsageLog.environment` — `production` | `development`, 기본값 `production`.

**왜 필요한가**: 개발용 Gemini 서비스 계정을 **따로 발급하지 않고 운영 키를 그대로 쓰기로**
결정했다. 그래서 청구는 한 프로젝트에 모이고, 개발 검증 호출과 실사용 호출을 갈라내는
유일한 수단이 이 컬럼이다. **원가 집계 쿼리는 반드시 `environment = 'production'`을 건다.**
빠뜨리면 개발 호출이 운영 원가로 잡히고, 원가 추적은 이 기능 존재 이유의 절반이다(1.4).

★**판정을 `NODE_ENV`로만 하면 안 된다.** `shared-api/.env`에 `NODE_ENV=production`이
**하드코딩**돼 있어 서버2(개발)에서도 그 값을 읽는다. 그대로 쓰면 개발 호출이 전부
production으로 기록돼 컬럼을 넣은 의미가 사라진다. 전용 변수 **`RP_ENVIRONMENT`를 먼저 보고**,
없을 때만 `NODE_ENV`로 폴백한다(`lib/reverse-prompt/constants.ts`의 `resolveEnvironment()`).
개발 검증 시에는 `RP_ENVIRONMENT=development`를 준다.

실측 확인(컨테이너): 운영 2건 + 개발 2건을 넣고 위 쿼리를 돌리면 **2건 / $0.0044**만
집계되고, 필터를 빼면 4건 / $0.0088로 개발분이 섞인다.

### 8.1 접근 제어

### ★AI 클라이언트 — 별도 Vertex 클라이언트를 쓴다 (2026-08-14)

이 기능은 기존 `lib/gemini.ts`의 `getGeminiClient()`를 **쓰지 않는다.**
그 함수는 `location: 'us-central1'` 하드코딩인데 `gemini-3.5-flash-lite`는 그 리전에 없어
**404**가 난다(6.1 리전 실측표 참조). `lib/gemini.ts`는 기존 파일이라 수정 대상이 아니므로,
`lib/reverse-prompt/vlm.ts`에 `location: 'global'` 전용 클라이언트를 따로 둔다.

**★그 결과 이 기능의 AI 호출은 기존 사용량 로깅 프록시에서 빠진다.**

`getGeminiClient(feature)`는 `models.generateContent`를 프록시로 감싸 응답의 `usageMetadata`를
`logGeminiUsage()` → `logAiUsage()` → **`AiUsageLog` 테이블**에 자동 기록한다.
전용 클라이언트는 그 프록시를 거치지 않으므로 **`AiUsageLog`에 아무것도 남지 않는다.**

실측 확인(2026-08-14): 묶음 B에서 실제 Gemini 왕복을 여러 번 했음에도
개발 DB의 `AiUsageLog`는 **0건**, `RpAiUsageLog`는 **28건**이었다.

→ **`RpAiUsageLog`가 이 기능의 유일한 AI 사용 기록처다.**
- 원가·사용량을 볼 때 `AiUsageLog`를 조회하면 이 기능은 **통째로 누락**된다. 반드시 `RpAiUsageLog`를 본다
- 대신 `RpAiUsageLog`는 기존 프록시가 못 하던 것을 한다:
  **실패 호출·캐시 적중까지 전건 기록**(PRD 6.2), `cacheHit`·`visitorKey`·`environment` 보유
- 그러므로 이 기능에서 `logAiUsage()`(store.ts)를 빠뜨리면 **그 호출은 어디에도 남지 않는다.**
  호출 경로를 추가할 때 반드시 함께 기록한다

## 11. 비용 통제 정책

**선택 사항이 아니다. 위반하는 구현은 완료로 인정하지 않는다.**

1. 분석 결과는 **1회만 생성**하고 저장한다. 결과 조회·보관함 열람·재접속 시 재생성하지 않는다
2. 이미지 해시가 일치하면 캐시에서 반환하고 AI를 호출하지 않는다
3. MJ와 SD를 **한 번의 호출로** 함께 받는다. 형식별로 나눠 호출하지 않는다
4. 이미지는 긴 변 1024px로 줄여서 전달한다. 원본 해상도를 그대로 넣지 않는다
5. 비로그인은 **하루 2회**, 로그인 사용자는 **하루 20회**로 제한하고 초과 시 429를 반환한다
6. 기계적으로 가능한 작업(형식 변환, 파라미터 문자열 조립, 정렬, 검색)에 AI를 쓰지 않는다
7. 모든 호출을 사용량 로그에 기록하고, SQL로 사용자당·일자별 원가를 조회할 수 있어야 한다
8. 일일 한도를 우회할 수 있는 경로를 만들지 않는다

**월 원가 상한**: `(입력 토큰 + 출력 토큰) × 단가 × 예상 호출수` 산식으로 계산해 확정한다.
**추정치를 문서에 적지 않는다.**

★한도 상한으로 계산한 이론적 최대: 로그인 20회/일 × 30일 = 월 600건/인 = 약 $0.74/인.

## 12. MVP 범위

**포함**
- S1 업로드 + 결과 화면
- S2 보관함 화면
- 이미지 → MJ/SD 프롬프트 분석 (1회 호출, 두 형식 동시)
- 이미지 전처리 (리사이즈·EXIF 제거·해시·썸네일)
- 해시 기반 분석 캐시
- 비로그인 일일 2회 / 로그인 일일 20회 한도
- 로그인 요구 시점의 입력값 임시 보관 및 복원
- AI 사용량 로그 및 원가 집계 쿼리
- aichat 메인에서의 진입점 (**노출 스위치는 마지막에 켠다**)

**제외 (구현 금지)**
- ComfyUI 재생성 미리보기 — V2
- 이미지 가공 기능 일체
- 일괄 업로드
- 프롬프트 공유·갤러리
- 결제 및 유료 플랜
- MJ·SD 외 형식
- 원본 이미지 서버 보관

## 13. MVP 완료 조건

전부 통과해야 완료다. **추정으로 통과 처리하지 않는다.**

- [ ] 이미지 1장 업로드 시 MJ 프롬프트와 SD(positive/negative) 프롬프트가 모두 표시된다
- [ ] 분석 1건당 AI 호출이 **정확히 1회**임을 로그 테이블로 확인할 수 있다
- [ ] 같은 이미지를 다시 올리면 `cacheHit = true`로 기록되고 AI 호출이 발생하지 않는다
- [ ] 보관함 항목을 다시 열어도 **재생성되지 않고** DB에서 로드된다
- [ ] 비로그인 3회차 시도 시 429와 로그인 모달이 뜬다
- [ ] 로그인 모달에서 이탈 후 로그인하고 돌아오면 올리려던 이미지가 복원된다
- [ ] 서버 파일시스템과 DB 어디에도 원본 이미지가 남지 않는다 (실제 확인)
- [ ] 업로드 이미지의 EXIF가 제거되어 VLM에 전달된다
- [ ] 타 사용자의 `RpItem`에 접근하면 404가 반환된다 (테스트 포함)
- [ ] 360px에서 S1, S2가 가로 스크롤 없이 표시된다
- [ ] 기존 aichat 기능이 전부 그대로 동작한다 (회귀 확인)
- [ ] 모든 AI 호출이 사용량 로그에 토큰 수·원가와 함께 기록된다
- [ ] 11장 원가 산식으로 실측 원가가 계산되어 문서에 기입되었다
- [ ] 빌드 및 테스트가 무오류로 통과한다
