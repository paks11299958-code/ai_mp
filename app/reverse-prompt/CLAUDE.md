# CLAUDE.md — 개발 지침

## 프로젝트

aichat.dbzone.kr에 **리버스 프롬프트** 기능을 추가한다. 제품 사양은 `PRD.md`가 **유일한 기준**이다. 이 문서는 개발 방식만 규정한다.
두 문서가 충돌하면 `PRD.md`를 따른다.

---

## 가장 먼저 할 일

1. `PRD.md`를 전부 읽는다.
2. `PRD.md` 0장의 "조사할 것" 10개 항목을 코드베이스에서 직접 확인한다. "이미 확인된 것" 표에 있는 항목은 다시 조사하지 않는다.
3. 파악한 내용을 **표로 요약해 보고한다.** 특히 인증 방식, 사용자 테이블명·PK 타입, Prisma 스키마 정본 경로는 실제 코드 인용과 함께 보고한다.
4. `PRD.md`의 전제와 다른 부분이 있으면 **명시적으로 지적한다.** 조용히 맞춰서 진행하지 않는다.
5. `PROGRESS.md`가 있으면 읽고 이어서 진행한다. 없으면 새로 만든다.

**추측으로 진행하지 않는다.** 특히 인증과 사용자 테이블 구조는 반드시 실제 코드를 확인한 뒤 결정한다.

---

## 작업 모드

- 자율 개발 모드로 진행한다. 단계마다 승인을 요청하지 않는다.
- 오류가 나면 스스로 원인을 찾아 수정하고 다시 테스트한다.
- 지시받은 묶음의 범위만 수행하고, 끝나면 보고하고 멈춘다.
- 막혀서 진행이 불가능할 때만 멈추고, 무엇이 왜 막혔는지와 시도한 방법을 보고한다.

## 배포 및 실행 순서

- **main 머지가 곧 운영 배포다. 머지는 사용자 승인 후에만 한다.**
- 배포 순서: DB 마이그레이션 → shared-api(백엔드) → 프론트엔드(Vercel) → 메인 진입점 노출 스위치
- 마이그레이션은 **파일 작성까지만.** 운영 DB 실행 전 SQL 전문·영향 테이블·백업 여부를 보고하고 승인받는다
- DDL에 기존 테이블 대상 `ALTER`/`DROP`이 있으면 **즉시 멈추고 보고한다**
- shared-api 재시작은 기존 aichat 서비스를 중단시킨다. **시점을 반드시 확인받는다**
- 메인 진입점 노출은 가장 마지막이다. 앞 단계가 전부 검증되기 전에 켜지 않는다

## 기존 코드 보호 원칙

이건 신규 프로젝트가 아니라 **운영 중인 시스템**이다. aichat은 지금 사용자가 쓰고 있다.

- 기존 파일 수정은 **라우터 등록 1줄, 메인 화면 진입점 링크 1개**로 한정한다. 그 외 기존 파일을 고쳐야 할 것 같으면 멈추고 물어본다
- 기존 테이블의 스키마를 변경하지 않는다. **신규 테이블만 추가한다**
- 신규 테이블·모델은 **`Rp` 접두사**를 붙이고, 0장 조사에서 확인한 기존 명명 규칙을 따른다
- Prisma 스키마 파일이 여러 벌이면 **정본에만** 추가한다. 사본은 수정하지 않는다. 어느 것이 정본인지 불확실하면 물어본다
- 신규 백엔드 코드는 **`shared-api/lib/reverse-prompt/`** 아래에 모은다
  (초판의 `src/reverse-prompt/`는 오류 — 이 저장소에 `src/` 디렉터리 자체가 없다)
- 신규 프론트 코드는 **`frontend/components/reverse-prompt/`** 아래에 모은다
  (초판의 `src/pages/reverse-prompt/`는 오류. 기존 `frontend/components/learning/` 선례를 따른다)
- 라우트 핸들러는 `shared-api/routes/aimp/reverse-prompt.ts` (기존 `routes/aimp/*` 관례)
- **기존 인증을 재사용한다. 새 인증 시스템을 만들지 않는다**
- 기존 라우팅·디자인 패턴을 따른다. 새 UI 라이브러리나 색상 체계를 도입하지 않는다
- 기존 공용 유틸을 수정해야 할 것 같으면 멈추고 물어본다
- 작업 후 기존 aichat 기능이 그대로 동작하는지 반드시 확인한다

사용자가 특정 묶음을 지정하면 그 묶음만 수행한다. **정의되지 않은 묶음 이름이 지시되면 범위를 확인받는다.**

### PROGRESS.md 갱신

각 단계를 마칠 때마다 **`ai_mp/app/reverse-prompt/PROGRESS.md`**를 갱신한다.

★**저장소 루트의 `PROGRESS.md`를 건드리지 않는다.** 그 파일은 **AI 학습코칭 전용 1243줄 문서**로
이미 존재하며, 덮어쓰면 학습코칭 개발 이력이 통째로 사라진다(초판은 "저장소 루트"라고
적었으나 오류다). 기획 문서 3종(`CLAUDE.md`/`PRD.md`/`PROGRESS.md`)은 학습코칭이
`app/learning/`에 두는 선례를 따라 `app/reverse-prompt/`에 모은다.

```markdown
# 진행 상황

## 완료
- [x] N. [항목] — 결과: [내용], 파일: [경로]

## 진행 중
- [ ] N. [항목] — 남은 작업:

## 다음 할 일

## 결정 사항
- [스스로 내린 기술 결정과 이유]

## 위험 요소
- [발견한 구조적 문제]

## 막힌 것 / 사용자 확인 필요
```

**규칙**
- 완료 항목에는 결과와 파일 경로를 함께 적는다. "완료"만 적지 않는다
- 스스로 내린 기술 결정은 반드시 남긴다. 다음 세션이 같은 결정을 다시 하지 않도록
- 컨텍스트가 압축되었다고 판단되면 `CLAUDE.md`, `PRD.md`, `PROGRESS.md`를 다시 읽는다

- 세션 사용자 ID는 항상 서버 세션에서 읽는다. 클라이언트가 보낸 값을 신뢰하지 않는다

- AI는 **HTTP API로 호출한다. 구독제 CLI를 쓰지 않는다** (약관·한도·부하·원가 측정 문제)
- ★**모델 은퇴 일정은 원문 표를 직접 열어 확인한다. 2차 출처를 믿지 않는다.**

  통해 널리 퍼져 있었고 공식 문서라고 제시되기까지 했으나, **공식 지원 중단 표를 직접 연
  결과 2.5-flash/2.5-flash-lite/2.5-pro 셋 다 "No shutdown date announced"**였다.
  반대로 **`gemini-3.1-flash-lite`는 2027-05-07 종료 + 대체 모델 `3.5-flash-lite`가 표에
  명시**돼 있었다 — 진짜 근거는 원문 표 안에 있었다.
  ★**"공식 문서에 있다"는 주장 자체를 검증 대상으로 삼는다**(사용자·나 양쪽 모두 틀릴 수 있다).
- ★**종료일이 없어도 모델은 끊길 수 있다.** 2026-07-09 `gemini-2.5-flash`가 종료일 공표 없이
  `404 NOT_FOUND: "no longer available"`를 반환해 프로덕션이 중단됐다(구글: "config 이슈, 롤백").
  → **모델명은 상수 1곳에만 두어 교체가 한 줄로 끝나게 한다.**
- ★**단가는 집계 사이트가 아니라 공식 가격표(`ai.google.dev/gemini-api/docs/pricing`)에서
  직접 확인한다.** 원가 수치는 산식이 아니라 실측(`countTokens`·실제 응답 `usageMetadata`)으로 적는다.
- ★**개발/운영 판정에 `NODE_ENV`를 단독으로 쓰지 말 것.**
  이 저장소는 `shared-api/.env`에 **`NODE_ENV=production`이 하드코딩**돼 있어
  **서버2(개발)에서도 `production`으로 읽힌다.** 그대로 판정하면 개발 호출이 전부
  운영으로 기록돼 원가 분리가 무력화된다(2026-08-14 실측 확인).
  → 전용 변수 **`RP_ENVIRONMENT`를 먼저 보고** 없을 때만 `NODE_ENV`로 폴백한다
  (`lib/reverse-prompt/constants.ts`의 `resolveEnvironment()`).
  ★**`.env`의 `NODE_ENV` 값 자체는 고치지 않는다** — `lib/logger.ts` 등 기존 aichat 코드가
  이미 참조하고 있어 로그 레벨 등 운영 동작이 바뀐다. 기존 파일 보호 원칙에도 어긋난다.
- API 키는 서버 사이드 전용. 클라이언트 번들에 포함하지 않는다
- 업로드 파일은 **디스크에 쓰지 않고 메모리에서 처리한다.** 처리 후 참조를 해제한다

### ★업로드 방식 — multer 아님 (2026-08-14 조사로 정정)

초판은 `multer.memoryStorage()`와 "미들웨어 레벨 용량 상한"을 전제했으나 **둘 다 이 저장소에 없다.**

- **multer가 설치돼 있지 않다.** 이미지는 `multipart/form-data`가 아니라
  **JSON body의 base64 문자열**로 받는다(`{ imageBase64, mimeType }` — `routes/aimp/outfit.ts` 선례).
- 용량 상한을 **미들웨어로 걸 수 없다.** `express.json({ limit: '10mb' })`가 `app.ts`에 전역으로
  걸려 있고, `app.ts`는 기존 파일이라 수정 금지 대상이다. 라우트별 파서를 덧대도 **이미 파싱된 뒤**다.
- 따라서 상한은 **핸들러 진입 직후 base64 문자열 길이로 검사**한다.
  원본 크기 ≈ `imageBase64.length × 0.75` (base64는 +33% 팽창). 초과 시 즉시 413.
- 프론트에서도 **파일 선택 즉시** 같은 상한으로 막아 413을 아예 보지 않게 한다(서버 검사는 그대로 유지).
- ★Vercel 프록시가 **10MB에서 순수 413**을 던진다(플랫폼 제약, 실측). Express 상한을 올려도
  그 앞단에서 막히므로 의미가 없다. 실질 상한은 이보다 낮게 잡아야 한다(PRD 7장 = 5MB).

### ★라우팅 — React Router 아님

프론트는 라우터 라이브러리를 쓰지 않는다. `App.tsx` 하단에서
`window.location.pathname`을 정규식으로 **수동 매칭**해 얼리리턴하는 방식이다
(`IS_LEARNING_INDEX` 등 학습코칭 선례 참조). 신규 화면도 이 패턴을 따르고,
`vercel.json`에 `{ "source": "/reverse-prompt", "destination": "/index.html" }` 규칙을
**catch-all(`/api/:d/...`)보다 앞에** 추가해야 한다(누락 시 화면·API가 조용히 404).

## 비용 규칙 (엄수)

`PRD.md` 11장을 위반하는 구현은 완료로 인정하지 않는다.

- 분석 결과를 다시 생성하지 않는다
- MJ와 SD를 나눠서 두 번 호출하지 않는다. **한 번의 응답에서 둘 다 받는다**
- 이미지를 원본 해상도로 VLM에 보내지 않는다. 반드시 1024px로 줄인다
- 캐시를 확인하지 않고 호출하지 않는다
- 일일 한도를 우회할 경로를 만들지 않는다
- 모든 AI 호출을 예외 없이 사용량 로그에 기록한다. 실패한 호출도 기록한다

**원가 관련 수치는 산식으로 계산한 것만 문서에 적는다.** 어림수를 그대로 인용하지 않는다.

## 테스트

- **단위**: 이미지 전처리(해시 일관성, EXIF 제거, 리사이즈 결과), 일일 한도 계산, MJ/SD 프롬프트 문자열 조립
- **통합**: 업로드 → 분석 → 보관 → 재조회 전체 왕복 1회
- **캐시**: 같은 이미지 2회 업로드 시 두 번째는 AI 호출이 발생하지 않음
- **보안**: 타 사용자 `RpItem` 접근 시 404
- **한도**: 비로그인 3회차 429, 로그인 21회차 429
- **회귀**: 기존 aichat 기능 정상 동작
- 시드 스크립트로 위 시나리오를 재현할 수 있어야 한다

**타입체크와 빌드 통과는 검증이 아니다.** 실제로 한 번 왕복해야 잡히는 결함이 있다.
